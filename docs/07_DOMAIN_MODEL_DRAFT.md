# 领域模型初稿

## 第六阶段前置子阶段 6A：证券主数据实体

- `Stock`：共享证券主数据实体，保留稳定 `id`，统一 `symbol` 为 `code.exchange`，保存交易所、市场、板块、证券类型、简称、全称、英文名、上市状态、上市/退市日期、历史简称、拼音、拼音首字母、来源、来源记录 ID、来源更新时间、最后同步时间、完整度和是否可搜索。
- `SecurityMasterSyncRun`：管理员人工发起的证券目录同步运行，保存触发用户、来源、交易所、状态、请求数、接收数、新增数、更新数、不变数、失败数、开始/完成时间、错误码、错误摘要和脱敏指标。
- `SecuritySourceRecord`：来源侧证券记录映射，保存股票、来源代码、来源证券 ID、来源 symbol、来源名称、原始元数据哈希、首次发现、最后发现和来源状态。
- `UserWatchlistItem`：用户私有自选股记录继续引用稳定 `stock.id`，只保存用户分组、标签、关注原因、备注、排序和归档状态，不保存或覆盖证券主数据。

不变量：股票改名不得创建新 `stock.id`；退市股票不删除；开发种子通过 legacy `data_source=development_seed` 保留原始迁移来源，真实来源同步相同 `symbol` 时更新原记录当前主数据字段和 `source_code`；普通搜索默认只返回可搜索的 A 股普通股票；证券主数据不包含行情、K线、财务、估值或 AI 结论。

## 第六阶段补充：外部来源与公告候选实体

- `ExternalSource`：统一外部来源注册实体，保存来源代码、显示名、发布机构、来源类别、权威层级、来源等级、地域、官方域名、访问方式、授权状态、再展示状态、商业使用状态、法律审查状态、健康状态、是否启用和是否实验。
- `ProviderSyncRun`：用户手动发起的 Provider 同步运行，保存来源、能力、触发用户、日期范围、请求股票、请求统计、记录统计、候选统计、错误码、Provider 元数据、开始和完成时间。
- `ProviderSyncState`：按用户、来源、能力和范围保存游标、重叠窗口、最近成功时间、最近公告发布时间、最近 Provider ID 和健康状态。
- `AnnouncementRecord`：共享公告元数据记录，不包含用户状态。保存来源、Provider 公告 ID、标题、公告类型、发布时间、公司、股票、来源页面、PDF 链接、哈希、去重键、完整度和采集时间。
- `UserAnnouncementCandidate`：用户私有公告候选，保存用户、公告记录、同步运行、处理状态、匹配类型、匹配股票、匹配依据、PDF 提取状态、已查看、忽略和导入时间。
- `InformationIngestionLink`：公告候选导入正式 InformationItem 的幂等链接，按用户隔离。

未来政府文件、国际官方文件和授权财经媒体仅保留 Pydantic 草案和文档设计，不在本阶段建表。`UserSettings` 不承载 AI 配置、公告来源、异动规则、标签、分组或管理员权限。

本文只定义实体、字段类别、关系和生命周期，不生成 SQL、迁移文件或 ORM 模型。

## 核心不变量

- 标准分类不能被用户覆盖。
- 系统建议可以被用户接受、拒绝或忽略。
- 用户标签、个人分组和关注逻辑独立保存。
- 原始公告、资讯和舆情来源不可被 AI 摘要覆盖。
- AI 复盘原始版本不可被用户编辑覆盖。
- 用户修改复盘必须形成新的修订版本。
- 行情和程序计算指标不能由 AI 生成或补全。
- 观察条件验证状态可以进入下一次复盘材料。
- AI 调用日志不长期保存完整原始输入、完整第三方正文、完整 Prompt、API Key 或模型隐藏推理。
- OpenID、UnionID 和外部通知绑定信息不得作为用户主键，也不得写入用户主表或普通个人设置。
- 通知严重度由程序规则决定，AI 不得提升严重度、修改通知偏好或改变通道状态。
- 外部通知通道失败不得阻断复盘、行情、估值、公告或站内通知。

| 板块内股票排名 | 股票、板块、交易日、排名、分数、排名依据、核心驱动、风险扣分、数据完整度、角色建议、置信程度 | 关联股票、板块热度快照和观察候选 | “龙头、中军、补涨、跟随”等只能作为系统建议，允许用户修正 |
| 次日观察候选 | 候选类型、股票或板块、入选原因、当前阶段、继续观察条件、失效条件、待核实事项、数据完整度、生成日期、公式版本 | 可回流到复盘和观察条件验证 | 不是交易建议，不包含买卖、仓位或收益保证 |
| 财务数据快照 | 股票、报告期、公告日期、数据取得日期、TTM/单季度/累计口径、财务字段、来源、单位、缺失字段 | 关联估值输入快照 | 不得使用目标日期之后披露的数据；单位和口径必须可追溯 |
| 估值输入快照 | 股票、目标日期、当前价格、市值、股本、财务字段、历史估值、行业估值、同行可比、输入来源、数据完整度 | 关联财务数据快照和估值结果 | 数据不足时保留缺失状态，不由 AI 补全 |
| 估值结果 | 股票、目标日期、财务报告期、选择方法、估值区间、隐含空间、置信等级、置信原因、假设、缺失字段、不适用原因、公式版本、输入来源 | 关联估值输入快照、复盘版本和 AI 解释 | 估值结果是模型估计，不是事实、价格目标、交易建议或收益保证 |
| 估值方法运行 | 方法名称、适用状态、输入字段、假设、输出区间、缺失原因、公式版本 | 归属估值结果 | `normalized_cycle` 和 `dcf_feasibility` 可以先记录可行性或不可用原因 |

## 关系说明

- 一个用户拥有一个主自选股池，自选股池由多个自选股条目组成。
- 一只股票可以被多个用户关注，但每个用户的标签、分组、关注逻辑和复盘彼此隔离。
- 股票基础信息、标准分类和行情数据属于共享基础数据；用户分类和复盘属于用户私有数据。
- 标准行业板块、标准概念板块、动态市场题材和用户标签必须分离保存；板块筛选不得依赖用户标签字段实现。
- 分时、日K和量化概览属于确定性行情或程序计算数据；AI 只能解释，不能生成、补全或覆盖。
- 公告和资讯可以作为共享外部材料，但用户补充内容、用户关联和用户笔记属于用户私有数据。
- AI 调用记录必须能追溯任务类型、模型和状态，但不得泄露完整 API Key。
- 数据同步任务是后台任务概念，用户侧只通过今日页、个股详情和设置页看到最后更新时间、同步状态、数据来源、部分失败提示和重新刷新入口。
- 用户设置只影响当前用户页面展示，不修改原始行情、公告、资讯、复盘、用户标签、分组、关注逻辑或其他用户数据。
- 全市场复盘、板块热度、热门股票和估值结果是共享基础数据或程序计算结果；用户对其形成的笔记、观察条件和复盘引用属于用户私有数据。
- 估值输入和估值结果必须保留报告期、公告日期、数据取得日期、公式版本和输入来源；不得把当前市值反向证明为合理价值。
- 业务事件由业务模块产生，通知编排器只消费结构化事件；每日复盘、估值、公告或行情模块不得直接调用微信公众号 API。
- 当前用户每日复盘只聚合用户私有信息中心数据，不读取全市场行情、估值或板块热度。
- 一个用户未来可以绑定多个外部通知通道；当前只真实支持站内通知，外部身份与通知偏好独立于普通个人设置。
- 一个业务事件当前最多产生一条站内通知和一条 `in_app` 投递记录；未来外部通道接入时可扩展多条通道投递。

## 生命周期重点

- 标准分类：数据源同步生成，用户不可修改原始记录。
- 板块筛选数据：标准行业和标准概念来自标准分类；动态市场题材来自系统建议或规则识别并允许用户确认；用户标签不参与标准板块口径。
- 分时走势：供应商能力未确认前不得承诺真实可用；Mock 原型可使用确定性本地数据展示。
- 日K线和量化概览：作为个股详情 MVP 材料，必须保留来源、数据时间和缺失状态。
- 用户设置：新用户默认使用系统默认值；用户保存后按本人独立生效；无效值不得保存；保存失败时继续使用上一次有效配置。
- 是否显示已退市股票：仅作为用户界面的显示过滤偏好，关闭显示不删除历史自选股、行情、资讯、复盘和用户笔记；重新开启后历史记录可以重新显示。具体停牌、退市和名称变更处理口径仍需在真实数据开发前确认。
- 系统建议：生成后进入待确认状态，用户可接受、拒绝或忽略。
- 舆情条目：录入后可经历待解析、解析成功、解析失败、待分析、分析完成、归档。
- 复盘：先形成 AI 原始版本、规则版本或用户手写版本；每次人工修改都创建新版本。
- 用户每日复盘：由服务端先生成 `rule_snapshot`，再由 AI 解释；输入未变化且非 force 时不新建版本；输入变化后标记 `stale`，用户主动重新生成后清除。
- 观察条件：从复盘中产生，下一交易日展示并由用户验证，验证状态可回流到后续复盘。
- 异动事件：由程序计算产生，AI 可解释但不能决定事件是否存在。
- 全市场每日快照：收盘后按数据源能力产生；如果只是有限样本，必须记录样本范围并禁止展示为全市场结论。
- 板块热度快照：由板块成分和历史行情计算生成；权重、阈值和最终公式版本需在真实数据开发前确认。
- 财务数据快照：只能在报告已披露且公告日期不晚于目标日期时进入估值输入；未来数据必须拒绝。
- 估值结果：随输入数据和公式版本产生，不覆盖历史版本；数据不足或模型不适用时保留不可用结果和原因。
- 用户外部身份：未来绑定成功后保存外部 Provider 用户 ID；解绑、取消关注、授权失效或通道不可用时更新状态，不删除业务历史。
- 业务事件：按当前事件目录生成，幂等键包含事件类型、用户、对象和业务日期或版本等字段，避免重复通知。
- 通知：站内通知失败不得回滚业务事件；过期和归档只影响展示状态。
- 通知投递记录：当前仅 `in_app`；未来外部通道失败时需保留脱敏错误和有限重试结果；禁止普通日志记录完整密钥、完整外部响应或完整临时凭证。

数据库 Session 认证已进入后端基线：浏览器只保存 HttpOnly Cookie 中的随机不透明 Token，数据库只保存 Token 哈希；退出、过期、用户禁用和修改密码后的其他会话吊销均由后端校验。该设计不使用 localStorage 保存认证凭证。
## 后端第二阶段领域模型补充

新增领域实体：

- `AIProviderConfig`：用户级 AI Provider 配置，保存 provider 名称、OpenAI Compatible Base URL、模型名称、启用状态、测试状态和加密后的 API Key。同一用户最多一个启用配置。
- `AITask`：AI 任务主记录，覆盖 Provider 测试和信息结构化分析，保存任务类型、目标对象、Provider、状态、Prompt 版本、Schema 版本和输入 hash。
- `AITaskAttempt`：AI 单次调用尝试，保存尝试次数、状态、HTTP 状态、耗时、Token、错误码和脱敏元数据。
- `InformationItem`：用户级信息条目，区分 `manual_text` 与 `public_url`，保存来源类型、标题、用户备注、重要/已读/归档和状态。
- `InformationSource`：信息来源记录，保存原始 URL、规范化 URL、URL hash、来源名称、发布时间、抓取状态、HTTP 状态、内容类型和抓取时间。
- `InformationContent`：信息正文版本，保存内容版本、来源、标题、正文、hash、字符数、抽取方法和抽取状态。
- `ContentFetchAttempt`：受控抓取尝试记录，保存尝试次数、状态、开始/完成时间、HTTP 状态、错误码、响应大小和最终 URL。
- `InformationAnalysisVersion`：AI 分析版本，保存结构化结果、状态、Provider、模型、内容 hash、Prompt/Schema 版本。
- `InformationStockRelation`：信息与股票的关系，区分 AI 建议、用户确认和用户拒绝。
- `InformationEntityMention`：AI 或用户识别出的行业、概念、公司、产品等实体提及。
- `VerificationItem`：待核实事项，来源于 AI 分析或用户后续处理。

建模边界：AI 接口配置、AI 调用日志、信息内容版本和业务分析结果分别建模，不塞入 `UserSettings`；AI 调用日志不长期保存完整第三方正文、完整 Prompt、API Key 或隐藏推理。

## 第七阶段 Checkpoint A 行情领域模型补充

新增实体：

- `MarketDataSource`：记录行情来源、授权状态、使用范围、生产启用状态、能力、健康状态、限制和更新时间。该实体不保存合同全文、Token 或完整 Provider 响应。
- `MarketDataSyncRun`：记录一次行情同步运行，包含来源、触发方式、状态、请求交易日、解析交易日、请求股票数、接收/新增/更新/不变/失败数量、错误码、脱敏摘要、指标和开始/完成时间。
- `StockDailySnapshot`：记录一只已存在股票在某个交易日、某个来源的日级快照，包含开高低收、前收、涨跌额、涨跌幅、成交量、成交额、换手率、量比、市值、PE/PB、是否交易、完整度、来源更新时间和获取时间。

核心约束：

- `stock_id + trade_date + source_code` 唯一。
- 行情同步只能关联现有 `stocks`，不得创建股票。
- 失败不清空历史快照。
- 同一来源同一交易日同时最多一个 `running` 同步。
- `TUSHARE_PRO` 默认未授权生产使用，`production_enabled=false`。
- AI 不得生成、补全或覆盖 `StockDailySnapshot` 字段。
