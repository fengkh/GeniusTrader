# MVP 验收标准草案

本文列出第一版 MVP 的可执行、可观察、可判断验收项。

| 编号 | 验收项 | 通过标准 | 失败示例 |
| --- | --- | --- | --- |
| AC-01 | 用户登录与数据隔离 | A 用户登录后只能看到自己的自选股、AI 配置、舆情和复盘 | A 用户能通过页面或请求访问 B 用户数据 |
| AC-02 | 管理员账户管理 | 管理员可创建、停用和重置测试用户密码；重置生成一次性临时密码并要求用户首次登录后修改；操作有审计日志 | 普通用户可访问管理员页面，或普通日志记录完整临时密码 |
| AC-03 | 自选股管理 | 支持逐只添加、粘贴代码列表和 CSV 导入；CSV 支持 `stock_code`、`group`、`tags`、`focus_reason`；重复和错误代码有明细 | Excel 导入被作为 MVP 必需能力 |
| AC-04 | 自选股上限处理 | 接近或超过设计上限时有明确提示，不造成数据异常 | 超出上限后静默丢失或重复写入 |
| AC-05 | 三层分类区分 | 标准分类、系统建议和用户标签在页面和数据上分离 | 用户编辑覆盖了标准分类 |
| AC-06 | 系统建议处理 | 用户可接受、拒绝或忽略动态题材和标签建议 | 系统建议自动变成权威事实 |
| AC-07 | 行情来源与更新时间 | 所有行情数字展示来源、交易日和最后更新时间；页面区分正常、同步中、数据过期、部分失败和完全失败 | 页面展示无来源行情数字，或数据失败导致整页不可用 |
| AC-08 | 程序计算指标 | 异动和指标展示异动类型、触发依据、对比基准、实际数据、规则版本和数据时间 | AI 自行判断确定性异动 |
| AC-09 | 公告和资讯追踪 | 公告资讯保存来源、发布时间、采集时间和原始链接 | AI 摘要覆盖原始事实 |
| AC-10 | 舆情链接录入 | 用户可保存链接和平台信息，并手动关联股票或板块 | 解析失败导致条目无法保存 |
| AC-11 | 舆情解析失败降级 | 解析失败时允许用户补充标题、正文、字幕摘要或个人说明 | 系统承诺所有平台链接均自动解析 |
| AC-12 | 博主关注 | 用户可维护平台、博主名称、ID、主页链接、备注和关注方向 | 产品承诺任意博主内容自动获取 |
| AC-13 | AI API 配置 | 用户可配置 Base URL、API Key 和模型名称并测试连接，密钥不回显 | 页面或日志展示完整 API Key |
| AC-14 | AI Gateway 边界 | AI 调用经过后端统一网关，前端不直接调用用户密钥 | 浏览器端直接调用第三方 AI API Key |
| AC-15 | AI 失败降级 | AI 失败时行情、指标、公告、用户数据和历史复盘仍可用；用户可手写复盘或重新生成 | AI 失败导致今日页整体不可用 |
| AC-16 | 单股复盘 | 单股复盘包含统一结构、来源引用、AI 原始版本、人工修订版本和下一交易日观察条件 | 用户编辑覆盖原始 AI 版本 |
| AC-17 | 整体复盘 | 整体复盘聚合当前用户自选股，保存历史版本和观察条件 | 聚合了其他用户数据或未来数据 |
| AC-18 | 事实观点传闻标记 | 未经证实传闻与事实、观点分开展示 | 传闻被写成已确认事实 |
| AC-19 | 禁止交易建议 | 复盘和 AI 输出不包含直接买入、卖出、仓位或收益保证 | 输出“明日买入”“目标收益” |
| AC-20 | 移动端基本可用 | 主要页面在手机浏览器可完成登录、查看、录入和复盘 | 核心操作只能在桌面完成 |
| AC-21 | 网页内通知 | 异动、待核实事项和待处理舆情只在网页内展示 | 第一版发送短信、邮件、微信或系统推送 |
| AC-22 | 公开仓库安全 | 仓库中不存在密钥、真实用户数据、真实导入导出文件 | 提交了 `.env` 或真实用户 CSV |
| AC-23 | 数据供应商中立 | 文档和实现不把未确认供应商写成确定方案 | 硬编码某供应商为唯一方案 |
| AC-24 | 严禁未来数据 | 历史复盘只使用目标交易日及之前的数据 | 复盘中引用目标日之后的信息 |
| AC-25 | 一级导航收敛 | 桌面端一级导航为今日、自选股、信息中心、复盘历史、设置；异动和个股详情不作为一级导航 | 桌面端出现独立异动中心或公告资讯中心一级导航 |
| AC-26 | 今日页信息优先级 | 今日页按数据状态、自选股表现、重大异动、重大公告资讯、板块/分组、舆情、整体复盘、待处理事项顺序展示 | AI 整体复盘放在客观行情和重大信息之前 |
| AC-27 | 个股详情信息优先级 | 个股详情按股票身份、三层分类、行情强弱、异动、公告资讯、舆情、关注逻辑、当日复盘、昨日观察条件、历史版本、用户笔记顺序组织 | 用户笔记或 AI 结论压过客观行情和来源信息 |
| AC-28 | CSV 导入容错 | 单条数据错误不导致整个文件失败；导入后展示成功、失败、重复和更新数量；更新已有字段需用户确认 | 任一错误行导致全文件失败，或重复股票静默覆盖 |
| AC-29 | 观察条件验证 | 昨日观察条件在次日今日页和个股详情展示；用户可标记已发生、未发生、部分发生、无法判断、不再适用 | 观察条件只能生成，不能次日验证 |
| AC-30 | AI 调用日志最小化 | AI 调用日志默认只保存元数据和关联业务结果 ID；不长期保存完整输入、第三方正文、完整 Prompt、API Key 或模型隐藏推理 | 调用日志长期保存完整 Prompt 或完整第三方正文 |
| AC-31 | 数据同步任务展示边界 | 用户侧只展示最后更新时间、同步状态、数据来源、部分失败提示、刷新入口和必要错误说明，不设置独立同步任务页面 | MVP 增加独立运维型同步任务页面 |
| AC-32 | 复盘导出边界 | Markdown 导出不作为核心 MVP 验收项，当前 Mock 可不设计导出按钮 | 将导出作为阻塞 MVP 的核心验收项 |
| AC-33 | 普通个人设置 | 用户可查看、修改并保存时区、日期展示格式、数字展示偏好、默认首页视图、是否显示已退市股票和基础界面偏好；刷新或重新登录后设置仍存在；不同用户设置隔离；无效设置不能保存；保存失败保留原设置；展示设置不修改行情、资讯或复盘原始数据 | 普通设置修改影响其他用户，或关闭显示已退市股票后删除历史自选股、行情、资讯、复盘或用户笔记 |

## 验收说明

- 每项验收应在进入开发阶段后拆成可测试场景。
- 当前文档不创建测试代码，只定义验收行为。
- 未通过的验收项应回到 PRD 或开放问题中处理，不应通过扩大 MVP 范围绕过。
