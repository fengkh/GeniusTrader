# MVP 验收标准草案

本文列出第一版 MVP 的可执行、可观察、可判断验收项。

| 编号 | 验收项 | 通过标准 | 失败示例 |
| --- | --- | --- | --- |
| AC-01 | 用户登录与数据隔离 | A 用户登录后只能看到自己的自选股、AI 配置、舆情和复盘 | A 用户能通过页面或请求访问 B 用户数据 |
| AC-02 | 管理员账户管理 | 管理员可创建、停用和重置测试用户密码；重置生成一次性临时密码并要求用户首次登录后修改；操作有审计日志 | 普通用户可访问管理员页面，或普通日志记录完整临时密码 |
| AC-03 | 自选股管理 | 支持逐只添加、粘贴代码列表和 CSV 导入；CSV 支持 `stock_code`、`group`、`tags`、`focus_reason`；重复和错误代码有明细 | Excel 导入被作为 MVP 必需能力 |
| AC-04 | 自选股上限处理 | 接近或超过设计上限时有明确提示，不造成数据异常 | 超出上限后静默丢失或重复写入 |
| AC-05 | 三层分类区分 | 标准分类、系统建议和用户标签在页面和数据上分离 | 用户编辑覆盖了标准分类 |
| AC-06 | 系统建议处理 | 用户可接受、拒绝或忽略动态题材和标签建议 | 系统建议自动变成权威事实 |
| AC-07 | 行情来源与更新时间 | 所有行情数字展示来源、交易日和最后更新时间；页面区分正常、同步中、数据过期、部分失败和完全失败 | 页面展示无来源行情数字，或数据失败导致整页不可用 |
| AC-08 | 程序计算指标 | 异动和指标展示异动类型、触发依据、对比基准、实际数据、规则版本和数据时间 | AI 自行判断确定性异动 |
| AC-09 | 公告和资讯追踪 | 公告资讯保存来源、发布时间、采集时间和原始链接 | AI 摘要覆盖原始事实 |
| AC-10 | 舆情链接录入 | 用户可保存链接和平台信息，并手动关联股票或板块 | 解析失败导致条目无法保存 |
| AC-11 | 舆情解析失败降级 | 解析失败时允许用户补充标题、正文、字幕摘要或个人说明 | 系统承诺所有平台链接均自动解析 |
| AC-12 | 博主关注 | 用户可维护平台、博主名称、ID、主页链接、备注和关注方向 | 产品承诺任意博主内容自动获取 |
| AC-13 | AI API 配置 | 用户可配置 Base URL、API Key 和模型名称并测试连接，密钥不回显 | 页面或日志展示完整 API Key |
| AC-14 | AI Gateway 边界 | AI 调用经过后端统一网关，前端不直接调用用户密钥 | 浏览器端直接调用第三方 AI API Key |
| AC-15 | AI 失败降级 | AI 失败时行情、指标、公告、用户数据和历史复盘仍可用；用户可手写复盘或重新生成 | AI 失败导致今日页整体不可用 |
| AC-16 | 单股复盘 | 单股复盘包含统一结构、来源引用、AI 原始版本、人工修订版本和下一交易日观察条件 | 用户编辑覆盖原始 AI 版本 |
| AC-17 | 整体复盘 | 整体复盘聚合当前用户自选股，保存历史版本和观察条件 | 聚合了其他用户数据或未来数据 |
| AC-18 | 事实观点传闻标记 | 未经证实传闻与事实、观点分开展示 | 传闻被写成已确认事实 |
| AC-19 | 禁止交易建议 | 复盘和 AI 输出不包含直接买入、卖出、仓位或收益保证 | 输出“明日买入”“目标收益” |
| AC-20 | 移动端基本可用 | 主要页面在手机浏览器可完成登录、查看、录入和复盘 | 核心操作只能在桌面完成 |
| AC-21 | 站内通知中心 | 每日复盘、公告、异动、观察条件、估值和系统事件可在站内通知中心展示，支持未读数、类型筛选、严重度、状态和目标页面跳转 | 通知缺少目标页面、跨用户展示，或通知失败导致复盘和行情不可用 |
| AC-22 | 公开仓库安全 | 仓库中不存在密钥、真实用户数据、真实导入导出文件 | 提交了 `.env` 或真实用户 CSV |
| AC-23 | 数据供应商中立 | 文档和实现不把未确认供应商写成确定方案 | 硬编码某供应商为唯一方案 |
| AC-24 | 严禁未来数据 | 历史复盘只使用目标交易日及之前的数据 | 复盘中引用目标日之后的信息 |
| AC-25 | 一级导航收敛 | 桌面端一级导航为今日、自选股、信息中心、复盘历史、设置；异动和个股详情不作为一级导航 | 桌面端出现独立异动中心或公告资讯中心一级导航 |
| AC-26 | 今日页信息优先级 | 今日页按数据状态、自选股表现、重大异动、重大公告资讯、板块/分组、舆情、整体复盘、待处理事项顺序展示 | AI 整体复盘放在客观行情和重大信息之前 |
| AC-27 | 个股详情信息优先级 | 个股详情按股票身份与最新价、分时/日K图表、量化概览、三层分类、关注逻辑、异动、公告资讯、舆情、当日复盘、昨日观察条件、历史版本、用户笔记顺序组织 | 分类标签、用户笔记或 AI 结论压过图表、量化指标和来源信息 |
| AC-28 | CSV 导入容错 | 单条数据错误不导致整个文件失败；导入后展示成功、失败、重复和更新数量；更新已有字段需用户确认 | 任一错误行导致全文件失败，或重复股票静默覆盖 |
| AC-29 | 观察条件验证 | 昨日观察条件在次日今日页和个股详情展示；用户可标记已发生、未发生、部分发生、无法判断、不再适用 | 观察条件只能生成，不能次日验证 |
| AC-30 | AI 调用日志最小化 | AI 调用日志默认只保存元数据和关联业务结果 ID；不长期保存完整输入、第三方正文、完整 Prompt、API Key 或模型隐藏推理 | 调用日志长期保存完整 Prompt 或完整第三方正文 |
| AC-31 | 数据同步任务展示边界 | 用户侧只展示最后更新时间、同步状态、数据来源、部分失败提示、刷新入口和必要错误说明，不设置独立同步任务页面 | MVP 增加独立运维型同步任务页面 |
| AC-32 | 复盘导出边界 | Markdown 导出不作为核心 MVP 验收项，当前 Mock 可不设计导出按钮 | 将导出作为阻塞 MVP 的核心验收项 |
| AC-33 | 普通个人设置 | 用户可查看、修改并保存时区、日期展示格式、数字展示偏好、默认首页视图、是否显示已退市股票和基础界面偏好；刷新或重新登录后设置仍存在；不同用户设置隔离；无效设置不能保存；保存失败保留原设置；展示设置不修改行情、资讯或复盘原始数据 | 普通设置修改影响其他用户，或关闭显示已退市股票后删除历史自选股、行情、资讯、复盘或用户笔记 |
| AC-34 | 自选股紧凑扫描列表 | 桌面端为高密度表格或紧凑行列表；移动端每只股票行控制在约80至100px，整行可进入详情，390×844左右视口在筛选收起后至少可看到4只完整股票行 | 移动端继续使用大型详情卡，单屏只能看到一至两只股票 |
| AC-35 | 板块筛选 | 自选股页支持标准行业板块、标准概念板块和动态市场题材三类板块筛选；同一时间只选一个主板块，并可与搜索、个人分组和用户标签叠加 | 板块只被当成普通用户标签，或不能与其他筛选条件组合 |
| AC-36 | 个股图表 | 个股详情提供日K图作为 MVP 内容；Mock 原型可展示分时图，真实分时能力取决于数据供应商；图表展示模拟数据标识、数据时间和 TradingView Lightweight Charts 归属说明 | 图表无数据来源和模拟标识，或把Mock图表描述为实时行情 |
| AC-37 | 量化概览数值化 | 个股详情量化概览至少展示5日、10日、20日涨跌幅、距20日高点、相对行业强度、相对指数强度、成交量/成交额/换手率/振幅历史分位、日内收盘位置和最大日内回撤，并包含数值、基准、可视化和数据时间 | 量化数据只用“强/弱/放量”等文字标签，不展示数值和比较基准 |
| AC-38 | AI 与确定性数据边界 | AI 可以解释图表和量化指标，但不得生成、补全或覆盖分时、K线、行情数字和程序计算指标；字段缺失时显示暂无数据或失败状态 | AI 在数据缺失时补造K线、成交量或量化指标 |
| AC-39 | 全市场复盘可行性报告 | Spike 报告回答全市场复盘能否实现、哪些指标可靠、哪些指标必须降级、免费方案是否足够和是否建议进入正式后端 | 用少量样本直接宣称全市场能力已具备，或缺少 Provider 缺口结论 |
| AC-40 | 板块热度可解释 | 板块热度每个维度保存原始值、标准化值、数据来源、计算日期、公式版本和缺失状态；总分可拆解 | 只输出一个“热门”或总分，无法追溯计算依据 |
| AC-41 | 板块内热门股票排名 | 排名展示排名依据、原始数值、板块内排名、核心驱动、风险扣分、数据更新时间和角色建议置信度 | 将“龙头”“中军”等系统建议表达为确定事实或投资推荐 |
| AC-42 | 次日观察候选边界 | 观察候选包含入选原因、当前阶段、继续观察条件、失效条件、待核实事项和数据完整度，不包含买入、卖出、仓位或收益保证 | 观察候选被写成明确交易指令 |
| AC-43 | 估值中心输出边界 | 估值中心输出估值方法、估值区间、隐含上涨或下跌空间、模型假设、财务数据日期、数据完整度、置信等级、缺失字段和无法估值原因 | 把模型估计写成确定事实，或强迫所有股票输出估值数字 |
| AC-44 | 估值数据和 AI 边界 | 估值只使用目标日期及之前已披露数据；程序选择模型并计算估值，AI 只能解释假设、敏感性、风险和缺口 | AI 生成财务数据、估值数字、模型选择或使用未来财务数据 |
| AC-45 | 全市场复盘 Mock 承载 | 今日页在自选股整体表现之后展示市场复盘摘要；`/market-review/[date]` 展示市场总览、宽度、指数、板块热度、板块内股票、次日候选、数据能力限制和 AI 摘要 | 全市场复盘新增一级导航，或有限样本被展示成确定全市场真实结论 |
| AC-46 | 市场复盘状态覆盖 | 市场复盘列表和详情覆盖完整复盘、部分数据复盘、数据源降级、AI 摘要失败、复盘生成失败和尚未生成状态 | AI 摘要失败导致程序计算的市场宽度、板块和候选不可见 |
| AC-47 | 个股估值 Mock 场景 | 个股详情估值中心覆盖稳定盈利 PE、银行 PB-ROE、成长 PS、分红、周期低置信、亏损不可估、财务过期和字段部分失败 | 所有股票都强行输出同一种估值方法或伪精确区间 |
| AC-48 | 通知偏好和通道边界 | `/settings/notifications` 展示站内通知开关、事件偏好、免打扰时间和微信公众号 Mock 状态，并明确未接入真实微信能力 | 页面发起真实 OAuth、扫码、SDK、模板消息或外部 API 调用 |
| AC-49 | 通知编排解耦 | 复盘、估值、公告、行情和观察条件模块只产生业务事件，不直接调用微信公众号；微信失败不影响站内通知和业务页面 | 每日复盘生成流程直接依赖微信发送成功 |
| AC-50 | 通知安全和最小披露 | 通知深链不包含 userId、OpenID、Token、API Key 或敏感账户信息；微信摘要不包含完整自选股清单、交易动作、仓位或保证性表述 | 用户 A 收到用户 B 的复盘通知，或外部摘要泄露密钥/完整自选股 |
| AC-51 | 后端数据库 Session 认证 | 登录成功设置 HttpOnly Cookie，数据库只保存 Session Token 哈希；JSON 不返回 Token；退出、过期、吊销和用户禁用均阻止继续访问 | 前端 localStorage 保存 Token，或数据库保存明文 Session Token |
| AC-52 | 后端用户数据隔离 | 自选股、分组和标签 API 的查询条件显式包含当前 `user_id`；跨用户读取、修改、删除或引用分组/标签被拒绝且不泄露资源归属 | 仅知道 UUID 即可读取或修改其他用户自选股 |
| AC-53 | 后端统一错误和请求 ID | 业务错误、参数错误、数据库不可用和内部错误均返回统一 `error.code/message/request_id`，响应头包含 `X-Request-ID` | 客户端看到 Python 堆栈、SQL、数据库连接信息或无请求 ID 的错误 |
| AC-54 | 后端审计和脱敏 | 管理员创建用户、登录、退出、修改密码、自选股、分组和标签关键操作写入审计日志，且不包含密码、临时密码、Session Token、Cookie 或数据库密码 | 审计 metadata 保存完整临时密码或 Session Token |
| AC-55 | 后端迁移和测试数据库隔离 | Alembic 升级成功；回滚验证只在 `geniustrader_test` 等明确测试库执行；测试不得清空开发库 | 为了跑测试直接 truncate 或 drop 开发库 `geniustrader` |
| AC-56 | 后端股票基础目录边界 | 股票基础 API 只返回本地 `stocks` 表基础信息，不返回行情、K线、板块、估值或 AI 结果 | 后端第一阶段硬编码真实行情 Provider 或返回模拟行情为真实数据 |

## 验收说明

- 每项验收应在进入开发阶段后拆成可测试场景。
- 当前文档不创建测试代码，只定义验收行为。
- 未通过的验收项应回到 PRD 或开放问题中处理，不应通过扩大 MVP 范围绕过。
## 后端第二阶段新增验收项

- 用户可以创建、查看、更新、删除自己的 AI Provider，且响应中不返回完整 API Key。
- AI Provider API Key 在数据库中为密文；测试连接只通过后端 AI Gateway 发起。
- 同一用户最多只有一个启用的 AI Provider。
- 用户可以创建手动信息条目，并生成内容版本和用户确认的股票关联。
- 用户可以提交单个公开 URL；私有地址、非 http/https、重复 URL、超限内容和不允许内容类型会被拒绝或保存失败状态。
- URL 抓取失败时，信息条目仍可见，用户可补充正文。
- 用户可以对有正文的信息条目发起 AI 结构化分析；结构化校验失败时最多修复一次，仍失败则保存失败分析版本。
- AI 建议股票关联默认为 suggested，用户可确认、拒绝或手动新增关联。
- 信息列表支持状态、来源类型、股票、重要、已读和关键词筛选。
- 不同用户的信息、AI Provider、分析版本和关联关系相互隔离。
- AI 失败或内容抓取失败不影响自选股、行情、公告原文、用户手动内容和历史数据查看。
