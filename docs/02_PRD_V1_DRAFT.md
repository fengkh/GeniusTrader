# GeniusTrader PRD V1 草案

本文是第一版产品需求草案，仅定义产品行为和验收边界，不包含技术实现、SQL、接口接入或业务代码。

## 功能 1：私人测试版账户与登录

- 目标：让受邀用户或管理员创建的用户安全进入系统，并保证个人数据隔离。
- 用户场景：用户收到账号后登录网页，查看自己的自选股、设置和复盘历史。
- 前置条件：管理员已创建账户或用户已通过邀请流程获得账户。
- 输入：账号标识、密码、登录设备信息。
- 处理流程：校验账号状态和密码；建立会话；加载用户级数据范围；记录登录操作日志。
- 输出：登录成功后的今日页，或明确的失败提示。
- 空状态：新用户无自选股时展示引导添加自选股的空状态。
- 错误状态：账号不存在、密码错误、账号停用、会话过期。
- 权限要求：普通用户只能访问本人数据；管理员只能执行被授权的账户管理动作。
- 验收标准：A 用户无法访问 B 用户自选股、AI 配置、舆情、复盘和日志。
- 是否属于 MVP：是。
- 方式：人工创建账户 + 系统自动登录校验。
- 数据来源和时间要求：账户创建、登录、重置和停用操作必须记录操作时间。
- AI 失败时的降级行为：不依赖 AI，登录和数据隔离必须正常。

## 功能 2：管理员账户管理

- 目标：支持私人测试版中的账户发放、停用和密码重置。
- 用户场景：管理员为测试用户创建账户，或在用户忘记密码时重置密码。
- 前置条件：操作者具备管理员权限。
- 输入：用户标识、初始状态、重置密码请求、停用或启用动作。
- 处理流程：校验管理员权限；管理员发起密码重置；系统生成一次性临时密码并设置有效期限；用户首次使用临时密码登录后必须修改密码；记录管理员审计日志；普通日志不得记录完整临时密码。
- 输出：账户状态变更结果、临时密码生成结果和有效期限提示。
- 空状态：暂无测试用户时显示创建账户入口。
- 错误状态：权限不足、目标用户不存在、重复账户、临时密码过期、重置失败。
- 权限要求：仅管理员可访问。
- 验收标准：普通用户看不到设置中的管理员账户管理；管理员无法读取用户原密码；管理员操作可追溯；第一版不做邮件重置流程。
- 是否属于 MVP：是。
- 方式：人工管理。
- 数据来源和时间要求：所有管理员操作必须保存操作者、目标用户、动作和时间。
- AI 失败时的降级行为：不依赖 AI。

## 功能 3：AI API 配置

- 目标：允许用户配置自带 AI API，并让所有 AI 调用经过统一 AI Gateway。
- 用户场景：用户填写 Base URL、API Key、模型名称、默认模型和备用模型，并测试连接。
- 前置条件：用户已登录。
- 输入：Base URL、API Key、模型名称、供应商类型、任务模型偏好。
- 处理流程：校验输入格式；后端加密保存 API Key；测试连接；保存脱敏状态；记录 AI 配置变更；AI 调用日志仅保存默认元数据。
- 输出：配置状态、测试结果、默认模型和备用模型状态。
- 空状态：未配置 AI 时，AI 任务入口显示“需先配置模型”。
- 错误状态：Base URL 无效、认证失败、模型不存在、网络失败、响应格式不兼容。
- 权限要求：用户只能管理自己的 AI 配置；前端不得读取完整 API Key。
- 验收标准：页面不展示完整 API Key；日志不保存完整 API Key；测试失败不影响非 AI 数据展示。
- 是否属于 MVP：是。
- 方式：用户人工配置 + 系统自动测试。
- 数据来源和时间要求：保存配置创建、更新时间和测试时间；不得保存真实密钥明文。
- AI 日志要求：默认只保存用户 ID、任务类型、模型、时间、Token 使用量、响应耗时、成功或失败状态、错误代码、输出结构校验状态和关联业务结果 ID；不长期保存完整原始输入、完整第三方正文、完整 Prompt、API Key 或模型隐藏推理。
- AI 失败时的降级行为：确定性行情、指标、公告、舆情原始记录和历史复盘仍可查看。

## 功能 4：普通个人设置

- 目标：允许用户调整与本人展示体验有关的基础设置，不影响原始行情、公告、资讯、复盘和其他用户数据。
- 用户场景：用户进入设置页，调整时区、日期格式、数字展示方式和基础界面偏好，使页面显示更符合个人习惯。
- 前置条件：用户已经登录。
- 输入：用户时区、日期展示格式、数字展示偏好、默认首页视图、是否显示已退市股票、基础界面偏好。
- 处理流程：校验设置值是否属于允许范围；按用户独立保存；设置只影响该用户的页面展示；设置不得修改底层原始数据；保存成功后相关页面使用新设置；设置保存失败时保留上一次有效配置。
- 输出：当前设置、保存成功提示、设置生效状态。
- 空状态：新用户没有保存过设置时，使用系统默认值。
- 错误状态：设置值无效、保存失败、服务暂时不可用、数据读取失败。
- 权限要求：普通用户只能修改自己的设置；管理员不得通过普通用户界面修改其他用户设置；所有读取和修改必须校验用户身份及数据归属。
- 验收标准：用户可以查看当前普通设置；用户可以修改并保存设置；页面刷新或重新登录后设置仍然存在；不同用户的设置相互隔离；无效设置不能保存；保存失败时保留原设置；修改展示设置不得修改行情、资讯或复盘原始数据。
- 是否属于 MVP：是。
- 方式：用户人工配置 + 系统校验。
- 数据来源和时间要求：设置变更记录用户、设置项、保存时间和生效状态；设置值只作为展示偏好，不作为外部事实来源。
- AI 失败时的降级行为：不依赖 AI，普通个人设置读写和展示应正常。

### “是否显示已退市股票”边界

- 该设置只是用户界面的显示过滤偏好。
- 该设置不代表系统已经完全确定退市股票的数据接入和生命周期处理方案。
- 关闭显示后，不删除历史自选股、行情、资讯、复盘和用户笔记。
- 重新开启后，历史记录可以重新显示。
- 具体停牌、退市和名称变更处理口径仍属于真实数据开发前需要确定的问题。

## 功能 5：自选股管理

- 目标：让用户建立和维护一个主自选股池。
- 用户场景：用户逐只添加股票、粘贴代码列表或导入 CSV，并为股票填写关注原因。
- 前置条件：用户已登录；股票基础信息源后续可用或存在可校验的股票基础数据。
- 输入：股票代码、CSV 文件、个人分组、标签、关注原因、核心逻辑。
- 处理流程：校验代码格式；匹配股票基础信息；去重；加入用户主自选股池；保存用户分类和关注逻辑。CSV 字段为 `stock_code` 必填，`group`、`tags`、`focus_reason` 选填；多个标签使用英文分号或中文分号分隔。
- 输出：自选股列表、添加结果、导入成功、失败、重复和更新数量。
- 空状态：无自选股时显示添加入口和 CSV 模板说明。
- 错误状态：代码无效、重复添加、超出上限、CSV 格式错误、单行数据错误、基础信息不可用。
- 权限要求：用户只能查看和管理自己的自选股。
- 验收标准：每位用户一个主自选股池；逐只添加、粘贴列表和 CSV 导入可用；单条 CSV 错误不导致整个文件失败；重复股票默认不重复创建；是否更新已有分组、标签和关注原因由用户确认；页面提供 CSV 模板下载示例；Excel 导入不出现在 MVP。
- 是否属于 MVP：是。
- 方式：人工输入 + 系统校验。
- 数据来源和时间要求：股票基础信息需记录来源和更新时间；用户填写内容记录创建和更新时间。
- AI 失败时的降级行为：自选股管理不依赖 AI；分类建议不可用时仍可手动维护。

## 功能 6：股票分类管理

- 目标：严格区分标准分类、系统建议和用户分类。
- 用户场景：用户查看股票所属行业和概念，接受或拒绝系统提出的动态题材建议，并维护个人标签。
- 前置条件：股票已存在于用户自选股池。
- 输入：标准分类数据、系统建议、用户接受/拒绝/忽略动作、用户分组和标签。
- 处理流程：展示标准分类；生成或导入系统建议；记录用户对建议的处理；独立保存用户分类。
- 输出：三层分类视图和处理状态。
- 空状态：无标准分类时显示“数据源暂未提供”；无系统建议时显示“暂无建议”。
- 错误状态：分类数据过期、建议生成失败、保存用户操作失败。
- 权限要求：用户只能操作自己的用户分类和建议状态，不得覆盖标准分类。
- 验收标准：标准分类不可被用户覆盖；系统建议可接受或拒绝；用户标签独立保存。
- 是否属于 MVP：是。
- 方式：标准分类自动导入；系统建议半自动；用户分类人工。
- 数据来源和时间要求：标准分类保存来源、分类体系和更新时间；系统建议保存生成时间和依据引用。
- AI 失败时的降级行为：标准分类和用户标签正常展示；AI 建议显示失败原因，可后续重试。

## 功能 7：行情数据与程序计算指标

- 目标：展示真实行情数据和由程序计算的确定性指标。
- 用户场景：用户查看自选股今日表现、OHLC、成交量额、换手率、市值、近期涨跌、相对强弱、数据来源状态和最后更新时间。
- 前置条件：后续数据供应商或合法数据源已配置；本轮不确定具体供应商。
- 输入：行情快照、日行情、指数和板块数据。
- 处理流程：以收盘后日级行情为基础；页面打开时可以触发刷新；用户可手动刷新；保存来源和更新时间；程序计算涨跌、振幅、量能、突破、相对强弱等指标；标注数据时点。
- 输出：行情表格、指标标签、相对表现、数据来源状态和最后更新时间。
- 空状态：暂无行情数据时显示数据源状态和最近一次可用数据。
- 错误状态：数据过期、同步中、部分失败、完全失败、字段缺失、口径不一致。
- 权限要求：登录用户可查看其自选股相关数据。
- 验收标准：所有行情数字有来源和更新时间；页面区分数据正常、同步中、数据过期、部分失败和完全失败；不承诺自动分钟刷新或实时行情；AI 不生成或补全行情数字。
- 是否属于 MVP：是。
- 方式：系统自动获取和程序计算。
- 数据来源和时间要求：每条行情和指标快照必须携带数据来源、交易日、采集时间和计算时间。
- AI 失败时的降级行为：不影响行情和指标展示。

## 功能 8：公告与资讯管理

- 目标：保存并展示可追溯的公告、交易所公开信息和重要资讯。
- 用户场景：用户在个股详情中查看当日公告、重大行业资讯和交易所公开信息。
- 前置条件：后续确定公告和资讯接入方案，或用户手动录入合法来源链接。
- 输入：标题、正文或摘要、来源、发布时间、采集时间、原始链接、关联股票和板块。
- 处理流程：采集或录入元数据；去重；关联股票和板块；区分正式披露、权威资讯、平台观点和未经证实传闻。
- 输出：公告资讯列表、来源标签、关联对象和原始链接。
- 空状态：无公告资讯时显示“暂无已收录信息”。
- 错误状态：来源不可访问、内容重复、发布时间缺失、关联失败。
- 权限要求：用户可查看与自选股相关的信息；用户私有补充内容仅本人可见。
- 验收标准：原始事实不被 AI 摘要覆盖；来源、发布时间、采集时间和链接可见。
- 是否属于 MVP：是。
- 方式：自动接入待定 + 用户可人工补充。
- 数据来源和时间要求：必须保存来源、发布时间、采集时间和原始链接。
- AI 失败时的降级行为：原始公告资讯仍展示；摘要和解释标记为未生成或失败。

## 功能 9：交易异动识别

- 目标：基于系统预设规则识别并展示交易异动。
- 用户场景：用户在今日页或异动聚合视图查看成交量异常、换手异常、振幅异常、背离等事件。
- 前置条件：行情、板块和指数数据可用；预设规则已定义。
- 输入：行情数据、板块/指数数据、资讯热度指标、规则配置。
- 处理流程：程序按官方和固定规则、历史分位规则、相对规则三类计算；生成异动事件；保存触发依据；展示对应数据。
- 输出：异动事件列表、异动类型、触发依据、对比基准、实际数据、规则版本、数据时间和影响对象。
- 空状态：无异动时显示“暂无触发预设异动规则”。
- 错误状态：必要数据缺失、规则配置不可用、计算失败。
- 权限要求：登录用户可查看自选股相关异动。
- 验收标准：AI 不决定确定性异动；每个异动展示异动类型、触发依据、对比基准、实际数据、规则版本和数据时间；本轮不确定具体阈值，阈值在真实数据接入和历史样本验证后决定。
- 是否属于 MVP：是。
- 方式：系统自动计算，普通用户暂不配置复杂阈值。
- 数据来源和时间要求：异动事件保存数据来源、交易日、计算时间和规则版本。
- AI 失败时的降级行为：异动计算不受 AI 失败影响；AI 解释不可用时仅展示程序结果。

## 功能 10：舆情收件箱

- 目标：让用户把外部讨论和内容线索纳入个人研究系统。
- 用户场景：用户粘贴抖音、小红书、雪球、同花顺、微信公众号或新闻网页链接，并补充标题、正文、字幕摘要或个人说明。
- 前置条件：用户已登录。
- 输入：链接、平台、标题、可合法获取的公开信息、用户补充文本、关联股票和板块。
- 处理流程：保存链接和元数据；尝试合法解析；解析失败则提示用户补充；手动或 AI 建议关联股票和板块；生成主题、情绪和信息质量分析。
- 输出：舆情条目、解析状态、关联对象、AI 分析和待核实事项。
- 空状态：无舆情条目时显示录入入口。
- 错误状态：链接无效、平台限制、解析失败、内容缺失、AI 分析失败。
- 权限要求：舆情条目属于用户私有数据。
- 验收标准：不承诺全平台解析；用户输入内容与原始来源信息分开保存；解析失败可降级为手动补充。
- 是否属于 MVP：是。
- 方式：用户人工录入 + 半自动解析和 AI 分析。
- 数据来源和时间要求：保存链接、来源平台、用户录入时间、原始发布时间和采集时间；无法获得时明确标记未知。
- AI 失败时的降级行为：条目和用户补充文本仍可保存、关联和查看。

## 功能 11：博主关注

- 目标：帮助用户管理关注的内容来源和后续手动录入流程。
- 用户场景：用户记录某平台博主，定期自行查看主页并录入新内容链接。
- 前置条件：用户已登录。
- 输入：平台、博主名称、博主 ID、主页链接、用户备注、关注行业/板块/股票。
- 处理流程：保存博主资料；校验主页链接；支持用户录入新内容链接；关联到舆情收件箱。
- 输出：博主列表、关注方向和内容条目。
- 空状态：无关注博主时显示添加入口。
- 错误状态：链接格式错误、重复关注、内容录入失败。
- 权限要求：用户只能管理自己的关注博主。
- 验收标准：不承诺任意博主内容自动获取；第一版采用人工确认式半自动关注。
- 是否属于 MVP：是。
- 方式：人工维护 + 半自动检查流程预留。
- 数据来源和时间要求：保存主页链接、录入时间和用户补充时间。
- AI 失败时的降级行为：博主管理不受影响；内容分析可稍后重试。

## 功能 12：单股每日复盘

- 目标：为每只自选股生成结构化每日复盘并允许人工修订。
- 用户场景：用户收盘后进入个股详情，查看行情、公告、资讯、舆情、异动和昨日观察条件验证状态后生成复盘。
- 前置条件：股票在自选股池中；目标交易日有可用数据或明确的数据缺失状态；用户已配置 AI 时可生成 AI 版本。
- 输入：行情、指标、异动、公告、资讯、舆情、关注逻辑、用户笔记。
- 处理流程：聚合当日材料；区分事实、观点、传闻和用户笔记；调用 AI 生成原始版本；用户可重新生成失败任务；AI 失败后用户可直接手写复盘；用户编辑形成修订版本。
- 输出：结构化单股复盘、AI 原始版本、人工修订版本、引用来源和下一交易日观察条件。
- 空状态：无足够材料时显示可用字段和缺失字段。
- 错误状态：AI 未配置、AI 失败、上下文过长、数据不足、保存版本失败。
- 权限要求：用户只能生成和查看自己的复盘。
- 验收标准：不输出买入、卖出或仓位指令；原始 AI 版本不可被覆盖；用户修改形成新版本；AI 失败后可以手写复盘或重新生成；观察条件可进入下一交易日材料。
- 是否属于 MVP：是。
- 方式：AI 生成 + 人工编辑。
- 数据来源和时间要求：复盘必须绑定交易日，引用材料保存来源和时间，严禁使用未来数据。
- AI 失败时的降级行为：展示确定性数据、公告资讯、舆情和手写复盘入口，允许稍后重新生成。

## 功能 13：自选股整体复盘

- 目标：聚合全部自选股生成当日整体复盘。
- 用户场景：用户在今日页查看全部自选股的主线、异动、风险和待核实事项。
- 前置条件：用户有自选股；目标交易日有部分可用数据。
- 输入：全部自选股行情表现、异动、公告、资讯、舆情、单股复盘摘要和用户笔记。
- 处理流程：聚合材料；按客观数据、事实、观点、传闻和 AI 判断分层；调用 AI 生成整体复盘；用户可重新生成失败任务；AI 失败后用户可直接手写整体复盘；用户确认或修订。
- 输出：整体复盘、重点股票、主要主题、风险、待核实事项和观察条件。
- 空状态：无自选股时引导添加；无当日数据时显示数据源状态。
- 错误状态：AI 未配置、AI 失败、数据过少、保存失败。
- 权限要求：只聚合当前用户的数据。
- 验收标准：不使用未来数据；不输出买卖建议和收益保证；可保存历史版本；AI 失败后可以手写整体复盘或重新生成。
- 是否属于 MVP：是。
- 方式：AI 生成 + 人工确认。
- 数据来源和时间要求：所有引用材料必须绑定来源、发布时间、采集时间和交易日。
- AI 失败时的降级行为：整体数据概览仍可用，整体复盘可手动记录或稍后重试。

## 功能 14：网页内通知与待处理事项

- 目标：在网页内提示异动、待核实信息和待处理舆情。
- 用户场景：用户打开今日页，看到需要关注的异动和未处理舆情。
- 前置条件：用户已登录；系统已生成异动或待处理状态。
- 输入：异动事件、舆情解析状态、待核实事项、AI 失败记录。
- 处理流程：聚合用户相关待处理事项；按优先级展示；用户可进入详情处理。
- 输出：网页内提醒列表。
- 空状态：无待处理事项时显示清爽状态。
- 错误状态：状态加载失败。
- 权限要求：只展示当前用户相关事项。
- 验收标准：第一版不发送短信、邮件、微信或系统推送。
- 是否属于 MVP：是。
- 方式：系统自动聚合 + 用户人工处理。
- 数据来源和时间要求：每条提醒显示产生时间和关联对象。
- AI 失败时的降级行为：AI 相关提醒显示失败状态；非 AI 提醒正常。

## 功能 15：用户可见数据状态与刷新

- 目标：让用户理解当前页面数据是否可用、是否新鲜，以及失败时哪些模块仍可继续使用。
- 用户场景：用户打开今日页或个股详情，看到数据日期、数据来源、最后更新时间和同步状态，并可手动刷新。
- 前置条件：用户已登录；后续数据源接入或已有历史数据。
- 输入：数据类别、来源、最后更新时间、同步状态、错误摘要、用户刷新动作。
- 处理流程：页面打开时可以触发刷新；用户可手动刷新；系统展示同步中、数据过期、部分失败或完全失败；其他可用模块继续展示。
- 输出：数据状态条、模块级状态、刷新结果和必要错误说明。
- 空状态：无任何可用数据时展示数据源尚不可用和手动刷新入口。
- 错误状态：单数据源失败、部分模块失败、全部数据失败、刷新过于频繁。
- 权限要求：用户只能看到与本人自选股相关的数据状态；管理员详细同步状态不属于当前 MVP 独立页面。
- 验收标准：行情、资讯、舆情或 AI 部分失败时，其他可用模块继续展示，不得导致整页不可用。
- 是否属于 MVP：是。
- 方式：系统自动展示 + 用户手动刷新。
- 数据来源和时间要求：每个模块必须显示来源、数据时间或最后更新时间。
- AI 失败时的降级行为：AI 状态仅影响 AI 模块，不影响确定性数据。

## 功能 16：观察条件验证

- 目标：让昨日复盘中的观察条件在次日被重新查看、标记和纳入下一次复盘。
- 用户场景：用户第二天打开今日页或个股详情，看到昨日观察条件，并根据当日事实标记验证状态。
- 前置条件：上一交易日存在单股或整体复盘，并生成了观察条件。
- 输入：观察条件、关联股票或整体复盘、目标交易日、用户验证状态和备注。
- 处理流程：在次日今日页和个股详情展示昨日观察条件；用户标记为已发生、未发生、部分发生、无法判断或不再适用；验证状态进入下一次复盘材料。
- 输出：观察条件验证状态、验证时间、用户备注和复盘材料引用。
- 空状态：无昨日观察条件时显示“暂无待验证观察条件”。
- 错误状态：历史复盘读取失败、保存验证状态失败、目标交易日不匹配。
- 权限要求：用户只能查看和标记自己的观察条件。
- 验收标准：观察条件可在次日展示；五种验证状态可保存；验证状态可进入后续复盘材料。
- 是否属于 MVP：是。
- 方式：用户人工标记 + 系统回流材料。
- 数据来源和时间要求：观察条件必须绑定来源复盘、交易日和验证时间。
- AI 失败时的降级行为：用户仍可人工标记观察条件。

## 本轮补充：自选股扫描、板块筛选、图表和量化概览

### 自选股紧凑扫描列表

- 目标：提升桌面端和手机端快速扫描自选股池的效率。
- 用户场景：用户在手机浏览器打开自选股页，希望在一个屏幕内快速看到多只股票的价格、状态、主板块、核心异动和走势方向。
- 前置条件：用户已登录并拥有自选股，或处于新用户空自选股场景。
- 输入：自选股、最新可用行情快照、个人分组、用户标签、标准行业、标准概念、动态市场题材、异动结果、20日迷你走势。
- 处理流程：按筛选条件得到结果集；桌面端使用高密度表格或紧凑行列表；移动端使用约80至100px高的紧凑行，整行可点击进入详情。
- 输出：股票名称、代码、状态、最新价、涨跌幅、一个主要行业板块、一个动态题材或概念、一个核心异动、20日迷你走势、数据状态。
- 空状态：无自选股时展示添加股票和 CSV 导入说明；无筛选结果时提示调整筛选。
- 错误状态：部分行情或板块数据缺失时，列表仍展示可用字段并标记状态。
- 权限要求：只展示当前用户自选股。
- 验收标准：移动端筛选收起后，在390×844左右视口至少可看到4只完整股票行；涨跌、停牌、过期和失败不能只依赖颜色表达。
- 是否属于 MVP：是。

### 板块筛选

- 目标：让用户按标准行业、标准概念和动态市场题材筛选自选股。
- 用户场景：用户希望只查看某个行业、概念或当日题材下的自选股，并与个人分组和用户标签叠加筛选。
- 前置条件：自选股已有关联的标准行业、标准概念或动态市场题材数据；供应商未确定时允许显示缺失状态。
- 输入：板块类型、板块名称搜索、当前自选股池、搜索关键词、个人分组、用户标签。
- 处理流程：显示“全部板块”；支持板块类型切换；展示当前自选股池常用板块及股票数量；同一时间只选择一个主板块；与其他筛选条件叠加。
- 输出：筛选结果数量、当前筛选条件、可清除全部筛选的入口。
- 空状态：无板块数据时提示分类暂不可用，个人分组和用户标签仍可使用。
- 错误状态：板块分类来源失败时标记缺失，不把用户标签冒充标准板块。
- 权限要求：只基于当前用户自选股池计算快捷板块数量。
- 验收标准：标准行业板块、标准概念板块、动态市场题材和用户标签在数据与页面上分离。
- 是否属于 MVP：是。

### 个股图表与量化概览

- 目标：让个股详情顶部优先呈现确定性行情走势和程序计算量化指标。
- 用户场景：用户进入个股详情，先查看最新价格、分时或日K、成交量和量化指标，再阅读分类、公告、舆情和复盘。
- 前置条件：股票在自选股中；日级行情和历史行情可用或有明确缺失状态。分时数据真实接入能力取决于未来数据供应商，Mock 原型可使用确定性本地数据展示。
- 输入：最新价、涨跌幅、分时价格、均价、昨收参考、分时成交量、日K开高低收、成交量、MA5、MA10、MA20、程序计算量化指标。
- 处理流程：个股详情顶部顺序为股票身份与价格、分时/日K图表、量化概览、分类标签、关注逻辑、后续复盘材料；日K为 MVP 内容；分时能力在真实数据开发前确认；量化指标必须由程序计算。
- 输出：分时图、日K图、成交量、均线、量化概览数值、比较基准、可视化位置、状态说明、数据时间和模拟数据标识。
- 空状态：无分时或K线数据时显示明确空状态，不补造数据。
- 错误状态：行情过期、部分字段缺失、成交量缺失或图表数据失败时，其他模块继续展示。
- 权限要求：用户只能查看本人自选股相关复盘材料；共享基础行情仍需按数据源授权约束展示。
- 验收标准：AI 不得生成、补全或覆盖分时、K线、行情数字和量化指标；量化概览不得只显示文字标签，必须包含数值和比较基准。
- 是否属于 MVP：日K和量化概览属于 MVP；真实分时接入能力待供应商确认，Mock 原型可展示。

### 全市场每日复盘与次日观察候选

- 目标：验证并设计收盘后全市场复盘能力，帮助用户先了解市场宽度、热门板块、板块持续性和次日观察线索，再回到个人自选股复盘。
- 用户场景：用户在今日页查看全市场总览、热门板块、退潮板块、板块内热门股票和次日观察候选，并把观察条件带入后续复盘材料。
- 前置条件：候选数据源能够提供全市场股票代码和状态、最近交易日行情、日线历史、主要指数、标准行业或概念板块、板块成分和股票与板块关系；如果缺失则展示缺失原因。
- 输入：全市场行情快照、历史日线、主要指数、板块成分、板块日线、成交额、换手率、振幅、涨跌停状态、停牌状态、公告和重大事件数量。
- 处理流程：程序计算上涨、下跌、平盘、停牌、涨停、跌停、成交额变化、20日新高新低、MA20以上比例、市场中位数涨跌幅、市场分层表现、板块热度、板块阶段、板块内热门股票和次日观察候选；AI 只能基于结构化结果生成解释。
- 输出：市场总览、主要指数表现、市场宽度、热门板块、连续走强板块、退潮板块、板块内热门股票、重点观察板块、重点观察股票、入选原因、继续观察条件、失效条件、风险和待核实事项。
- 空状态：数据源不能提供全市场或板块数据时，页面展示不可用模块和缺失原因，不用少量样本冒充全市场。
- 错误状态：部分数据源失败时保留可用的行情、板块或指数结果；完全失败时展示失败状态、来源和降级方案。
- 权限要求：全市场基础数据按数据源授权约束展示；用户个人观察记录仍按用户隔离。
- 验收标准：每个板块热度维度必须保存原始值、标准化值、数据来源、计算日期、公式版本和缺失状态；热门股票排名必须展示依据、原始数值、板块内排名、核心驱动、风险扣分和数据更新时间。
- 是否属于 MVP：本阶段为可行性 Spike 和后续能力候选；是否进入正式后端开发、是否先补 Mock 页面，需产品负责人基于 Spike 报告确认。

### 个股估值中心

- 目标：验证每只股票能否基于已披露财务数据、行情数据和行业可比数据形成可解释的估值区间和估值置信等级。
- 用户场景：用户进入个股详情后查看当前市场定价、财务数据日期、估值方法、悲观/基准/乐观估值区间、隐含上涨或下跌空间、模型假设、数据完整度和无法估值原因。
- 前置条件：估值仅可使用目标日期及之前已披露、可追溯的数据；不得使用未来财务数据，不得由 AI 补全财务字段或估值数字。
- 输入：当前价格、总市值、流通市值、总股本、流通股本、EPS、TTM净利润、营业收入、TTM营业收入、净资产、每股净资产、ROE、毛利率、净利率、经营现金流、自由现金流或可计算字段、资产负债率、有息负债、现金及等价物、分红记录、历史 PE/PB/PS、行业估值中位数、同行业可比公司、报告期、公告日期和数据取得日期。
- 处理流程：程序归一化财务字段和日期口径，禁止未来数据；程序根据公司类型和数据完整度选择 `stable_pe`、`pb_roe`、`ps_growth`、`dividend_yield`、`normalized_cycle`、`dcf_feasibility` 或 `insufficient_data`；AI 只能解释模型选择、假设含义、敏感性、风险和数据缺口。
- 输出：`symbol`、`as_of_date`、`financial_period`、`current_price`、`current_market_value`、`selected_methods`、`fair_value_low`、`fair_value_base`、`fair_value_high`、`implied_return_low`、`implied_return_base`、`implied_return_high`、`confidence_level`、`confidence_reasons`、`assumptions`、`missing_data`、`not_applicable_reasons`、`formula_version` 和 `input_sources`。
- 空状态：数据不足时输出 `confidence_level: unavailable`、缺失字段和不适用原因，不强迫所有股票产生估值数字。
- 错误状态：财务数据源失败、单位口径不明、报告期晚于目标日期、行业可比数据缺失或估值模型不适用时，展示不可用原因和降级方案。
- 权限要求：估值计算使用共享基础数据；用户个人备注、估值解释收藏和复盘引用按用户隔离。
- 验收标准：估值结果必须明确为模型估计，不是事实、交易建议、收益保证或价格目标；成交量、成交额和换手率只能影响流动性和置信度，不得直接证明内在价值。
- 是否属于 MVP：本阶段为可行性 Spike 和后续能力候选；正式页面和后端开发顺序需产品负责人基于 Spike 报告确认。
