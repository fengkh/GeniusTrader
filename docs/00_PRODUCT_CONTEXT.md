# GeniusTrader 产品上下文

本文记录第一版产品文档基线所依据的已确认产品决策。以下内容不应再被列为开放问题。

## 产品定位

GeniusTrader 第一版聚焦“A 股自选股复盘闭环”。产品帮助用户管理个人自选股、整理行情和公告资讯、沉淀舆情线索、生成每日复盘，并保存关注逻辑变化。

GeniusTrader 不是交易系统，不接入券商账户，不提供自动交易、买卖点、跟单、荐股、收益预测或收益承诺。

## 产品形态

- 第一版为响应式网页，同时适配桌面和手机浏览器。
- 后续可以升级为 PWA 或封装 App。
- 第一版部署目标为 Linux 服务器。
- 后续工程应支持 Docker Compose 部署，但当前文档基线阶段不得创建相关工程文件。

## 页面与导航

桌面端第一版一级导航确定为：今日、自选股、信息中心、复盘历史、设置。

- 今日：承载数据日期、来源状态、最后更新时间、自选股整体表现、重大异动、重大公告与重要资讯、板块及个人分组表现、舆情变化与待核实信息、今日整体复盘、待处理舆情与未完成复盘。
- 自选股：承载自选股列表、分组与标签、批量导入和个股详情。个股详情不是一级导航。
- 信息中心：通过 Tab 或二级导航承载公告与资讯、舆情收件箱、博主关注和待核实信息。
- 复盘历史：当前承载真实用户私有信息每日复盘、历史版本、AI 解释和来源追溯；单股每日复盘、自选股整体复盘和全市场复盘仍按产品边界继续迭代。
- 设置：承载 AI 接口配置、模型任务配置、个人设置、数据源状态和管理员账户管理。管理员账户管理仅对管理员可见。

移动端底部导航建议为：今日、自选股、信息、复盘、更多。设置和管理员功能放入“更多”。

## 用户体系

- 第一版按私人测试版设计。
- 支持邀请或管理员创建账户。
- 暂不开放公众自由注册。
- 第一版不做邮件验证和自助邮件找回密码。
- 允许管理员重置用户密码。
- 私人测试版密码重置采用一次性临时密码；用户首次使用临时密码登录后必须修改密码。
- 正式公开前必须补充完整账户验证与找回机制。
- 所有个人数据必须按用户严格隔离。

## 股票范围

- 数据模型覆盖沪深主板、创业板、科创板和北交所的在市 A 股。
- 第一版具体可用范围取决于后续数据供应商能力。
- 文档不得承诺尚未确认的数据覆盖能力。

## 行情实时性

- 第一版以日级行情和收盘后复盘为基础。
- 产品应支持展示最新行情快照及最后更新时间。
- 页面打开时可以触发刷新，并提供用户手动刷新入口。
- 页面必须区分数据正常、同步中、数据过期、部分失败和完全失败状态。
- 分钟级行情仅作为数据源能力允许时的增强功能。
- 第一版不承诺自动分钟刷新，不做逐笔行情、秒级刷新和高频监控。
- 所有页面必须明确展示数据来源和更新时间。
- AI 不得自行生成、估算或补全行情数字。

## 自选股结构

- 每位用户拥有一个主自选股池。
- 通过个人分组和标签进行管理。
- 第一版不开发多个彼此独立的自选股池。
- 技术设计可暂按每位用户最多 200 只自选股考虑。
- 第一版支持逐只添加、粘贴股票代码列表和 CSV 导入。
- CSV 字段确定为：`stock_code` 必填，`group`、`tags`、`focus_reason` 选填；多个标签使用英文分号或中文分号分隔。
- CSV 单条数据错误不得导致整个文件导入失败；导入完成后展示成功、失败、重复和更新数量。
- 重复股票默认不重复创建；是否更新已有分组、标签和关注原因由用户确认。
- 页面提供 CSV 模板下载示例。
- Excel 导入暂不属于 MVP。

## 股票分类体系

股票分类分为三个层级：

1. 标准分类：来自数据供应商的行业、概念和其他标准分类，保存来源、分类体系和更新时间。用户不得覆盖原始标准分类。
2. 系统建议：由规则或 AI 根据行情、公告、资讯和舆情提出，包括动态市场题材、股票角色等，必须标注为系统建议。用户可接受、拒绝或忽略。
3. 用户分类：用户自定义分组、标签、关注原因和核心逻辑，独立保存，不修改原始分类记录。

动态市场题材在第一版中只能作为“AI 或规则建议 + 用户确认”的内容，不得表现为权威事实。

## 舆情内容

- 第一版以用户粘贴独立链接和补充文本为主要方式。
- 支持来源类型包括抖音、小红书、雪球、同花顺、微信公众号和新闻网页等。
- 不承诺所有平台链接均可自动解析。
- 解析失败时允许用户粘贴标题、正文、字幕摘要或个人说明。
- 第一版不进行抖音、小红书全站爬取。
- 第一版不做图片理解和 OCR。
- 可预留未来图片上传和多模态分析能力，但不得纳入当前 MVP。
- 用户输入内容必须与原始来源信息分开保存。

## 博主关注

- 保存平台、博主名称、博主 ID、主页链接、用户备注和关注方向。
- 第一版采用人工确认式半自动关注。
- 用户自行查看主页并录入新内容链接。
- 不承诺任意博主内容可以自动获取。
- 官方接口或稳定数据能力作为后续扩展。

## AI 接入

- 第一版仅采用用户自带 API Key，平台暂不提供公共模型额度。
- 第一版优先支持 OpenAI Compatible 协议。
- 用户自行填写 Base URL、API Key 和模型名称。
- 不得把 DeepSeek V4 的具体模型名称硬编码到产品中。
- 架构应预留 Anthropic 及其他供应商适配能力。
- 所有调用必须经过后端统一 AI Gateway。
- 前端不得直接接触或调用用户 API Key。
- API Key 必须加密保存，日志不得保存完整 API Key。
- AI 失败时，确定性行情、指标、公告和用户数据仍应正常展示。
- “反方证据检查”是单股及整体复盘生成流程中的内部辅助任务，不设置独立页面和独立用户功能。
- AI 调用日志默认只保存用户 ID、任务类型、模型、时间、Token 使用量、响应耗时、成功或失败状态、错误代码、输出结构校验状态和关联业务结果 ID。
- 默认不在调用日志中长期保存完整原始输入、完整第三方正文、完整 Prompt、API Key 或模型隐藏推理。
- AI 生成的结构化复盘结果作为业务数据保存在复盘及版本实体中，不重复作为完整调用日志保存。
- 调试信息必须脱敏并设置自动过期机制。

## AI 信息质量分析边界

AI 不得直接宣称某条内容“真实”或“虚假”，也不应给出未经验证的绝对可信度概率。AI 只允许分析来源等级、原始出处、正式公告引用、交叉验证证据、事实/观点/传闻类型、证据完整程度、待核实问题，以及是否可能存在重复搬运或夸大表达。

## 第四阶段真实闭环边界

- 当前已实现真实 API 的页面包括 `/login`、`/information`、`/information/[itemId]`、`/settings/ai`、`/reviews`、`/reviews/[reviewId]`、`/notifications` 和 `/settings/notifications` 的站内通知部分。
- 用户每日复盘当前只聚合用户保存并分析的信息，不代表全市场行情复盘。
- 站内通知当前只真实支持 `in_app`；微信公众号、邮件、Web Push、移动 Push 和短信仍未接入。
- 6A 起 `/watchlist` 自选股管理接真实 API；第七阶段 Checkpoint A 起 `/today`、`/watchlist`、`/watchlist/[stockId]` 和 `/settings/market-data` 接入真实行情状态契约。
- 生产发布默认关闭未获授权真实行情和 Mock 行情；无授权行情时页面显示“暂无经授权的真实行情数据。”，不得展示模拟价格、K 线、分时或 AI 生成行情数字。
- 第七阶段 Production Release Gate 起，早期融合原型中的 `/market-review/[date]` 不再展示 Mock 全市场复盘、指数宽度、估值区间或模拟行情数字；该路由仅保留安全关闭说明，等待真实数据源、授权和验收口径确认后再评估开放。
- 证券基本信息来自证券目录同步；财务、估值、全市场宽度和正式行情 Provider 授权仍未冻结。

产品字段应优先使用“信息质量”“证据状态”“核验状态”“待核实事项”等表述，而不是武断真假判断。

## 异动规则

- 第一版采用系统预设规则，并按官方和固定规则、历史分位规则、相对规则三类组织。
- 官方和固定规则包括交易所异常波动、涨停/跌停或触及涨跌停、突破或跌破、明显高开低走、尾盘异常变化等。
- 历史分位规则包括成交量、成交额、换手率、振幅、日内回撤等，应相对于股票自身历史数据判断。
- 相对规则包括个股相对板块或主要指数明显背离、板块上涨但个股下跌、舆情热度上升但价格表现转弱等。
- 本轮只确定规则分类和展示方式，具体阈值在真实数据接入和历史样本验证后决定。
- 规则应配置化，不应散落在代码中。
- 第一版普通用户暂不配置复杂异动阈值。
- 后续可以增加用户自定义。
- 所有异动必须展示异动类型、触发依据、对比基准、实际数据、规则版本和数据时间。
- AI 不得自行决定是否发生确定性交易异动。

## 复盘结构

每只股票每日复盘采用统一结构：当日客观表现、相对板块和主要指数强弱、量价及交易异动、公告与重要事件、舆情关注度和主要话题、事实/观点/传闻区分、原关注逻辑变化、风险和待核实事项、下一交易日观察条件、用户个人笔记。

复盘不得输出直接买入、卖出或仓位指令。AI 原始版本必须保留，用户每次修改形成新的修订版本，不得覆盖或删除原始 AI 版本。

昨日观察条件必须在次日今日页和个股详情中展示。用户可以将观察条件标记为已发生、未发生、部分发生、无法判断或不再适用；验证状态可以进入下一次复盘材料。AI 失败后，用户可以直接手写复盘；用户也可以对失败任务重新生成。

## 产品通知

第一版不做短信、邮件、微信或系统推送，只在网页内展示异动、待核实信息和待处理舆情。

## 数据同步任务

`数据同步任务`保留为领域实体和后台任务概念，但不设置独立用户页面。用户侧仅展示数据最后更新时间、当前同步状态、数据来源、部分失败提示、重新刷新入口和必要错误说明。管理员侧未来可以查看更详细的同步任务状态，但不得扩大为当前 MVP 独立运维系统。

## 用户设置范围

`UserSettings` 的 MVP 范围仅包含时区、日期和数字展示偏好、默认首页视图、是否显示已退市股票、基础界面偏好。AI 接口、模型任务、用户标签、异动规则和管理员权限必须使用独立领域实体，不得全部塞入 `UserSettings`。

## 测试规模

第一版实际首批私人测试用户控制在 10 人以内，技术容量按 50 人以内进行合理验证。不得为该规模引入微服务或复杂分布式架构，数据库和业务逻辑不得写死 10 人限制。

## 复盘导出

Markdown 导出不作为核心 MVP 验收项，记录为 P1 增强功能。当前 Mock 原型可以不设计导出按钮，但不得删除未来数据可携带性的产品要求。
