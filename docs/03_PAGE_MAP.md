# 页面信息架构

## 第六阶段补充：公告试点页面

- `/settings/sources`：归入“设置”。展示外部来源注册表、公告 Provider 状态、授权与实验状态、未来来源分组。仅展示，不提供来源编辑、自动调度或真实 Provider 授权配置。
- `/information/announcements`：归入“信息中心”。承载公告候选收件箱、实验说明、手动同步入口、来源状态、候选筛选、候选列表和基础操作。
- `/information/announcements/[candidateId]`：归入“信息中心”详情页。展示公告元数据、来源等级、授权状态、匹配依据、PDF 提取状态、导入模式、导入后的 InformationItem 链接和实验说明。
- 桌面端不新增一级导航；入口从“信息中心”和“设置”进入。
- 移动端不新增第六个底部导航；公告候选位于“信息”，来源状态位于“更多/设置”。
- 所有公告页面必须显示实验阶段提示，不得呈现为稳定生产公告数据服务。

本文定义 GeniusTrader 第一版响应式网页的信息架构。页面描述不代表视觉原型或前端实现。

## 信息优先级

今日页内容顺序确定为：

1. 数据日期、数据来源状态和最后更新时间。
2. 自选股整体表现。
3. 全市场每日复盘摘要。
4. 今日重大异动。
5. 重大公告与重要资讯。
6. 板块和个人分组表现。
7. 舆情变化与待核实信息。
8. 今日整体复盘。
9. 待处理舆情和未完成复盘。
10. 未读通知概览。

个股详情内容顺序确定为：

1. 股票名称、代码、上市市场、当前状态、最新价和涨跌幅。
2. 分时和日K图表。
3. 量化概览。
4. 估值中心。
5. 标准分类、系统建议和用户标签。
6. 用户关注逻辑摘要。
7. 当日交易异动。
8. 公告与资讯时间线。
9. 舆情内容和博主观点。
10. 当日复盘。
11. 昨日观察条件及今日验证状态。
12. 历史复盘和修订版本。
13. 用户笔记。

## 全局导航建议

- 桌面端：左侧主导航，包括今日、自选股、信息中心、复盘历史、设置。
- 移动端：底部导航包括今日、自选股、信息、复盘、更多；设置、通知设置和管理员功能放入“更多”。
- 全局顶部应显示当前用户、数据更新时间概览、Mock 场景和通知铃铛入口；登录后通知铃铛读取真实未读数量，未登录不请求通知 API。

## 全局状态规则

- 每个展示外部数据的模块必须显示来源和更新时间。
- 每个 AI 输出模块必须显示生成时间、模型名称、任务类型和是否为 AI 原始版本。
- AI 失败不能遮挡确定性行情、指标、公告和用户自有数据。
- 未经证实传闻必须与事实和观点区分展示。
- 数据过期、同步中、部分失败和完全失败必须有不同页面状态。
- 行情、资讯、舆情或 AI 部分失败时，其他可用模块继续展示，不得导致整页不可用。
- 个股详情中，行情图表和程序计算量化指标的视觉层级必须高于分类标签和 AI 复盘；AI 不得生成或补全分时、K线和量化指标数字。

## 全市场复盘、估值与通知页面承载

本阶段新增能力进入融合 Mock 原型，不调整已确认的桌面一级导航。页面承载如下：

- 今日页：在自选股整体表现之后增加全市场复盘入口和摘要模块，展示市场宽度、主要指数、全市场成交额、涨跌家数、涨跌停数量、热门板块、连续走强板块、退潮板块和次日观察候选。模块必须标注数据范围，有限样本不得显示为全市场结论。
- 全市场复盘详情 `/market-review/[date]`：承载板块热度排行、板块阶段、板块热度组成维度、板块内热门股票和观察候选明细。板块热度总分必须可展开查看原始值、标准化值、公式版本、来源和缺失状态。
- 个股详情页：在行情图表和量化概览之后增加“估值中心”模块，展示当前市场定价、估值方法、估值区间、估值置信等级、模型假设、数据完整程度和不适用原因。估值模块不得压过行情图表、公告和复盘事实材料。
- 复盘历史页：当前 `/reviews` 接真实用户私有信息每日复盘 API；全市场每日复盘入口和状态仍为 Mock，不扩展为独立一级导航。
- 通知中心 `/notifications`：通过顶部铃铛、今日页摘要或移动端更多入口进入，集中展示真实站内通知。
- 通知设置 `/settings/notifications`：站内通知偏好接真实 API；微信公众号区域仅展示“尚未接入”的未来规划，不实现真实 OAuth、扫码、SDK 或发送。
- 设置页：数据源状态中可展示全市场、板块、财务和估值数据能力状态；不得扩展为独立运维系统。

移动端展示建议：

- 今日底部导航仍为入口，优先展示市场宽度摘要和热门板块前若干项，详细排行进入二级视图。
- 个股详情的估值中心采用紧凑分组卡片：先显示估值区间和置信等级，再展开模型假设、缺失字段和不适用原因。
- 次日观察候选必须使用“观察条件”和“失效条件”文案，不出现买入、卖出、仓位或收益保证。
## 后端第二阶段页面承载补充

- 信息中心的“舆情收件箱”和“公告与资讯”应承载两类录入入口：手动文本录入和单个公开 URL 录入。URL 抓取状态至少区分 `submitted`、`fetching`、`fetch_failed`、`ready`、`analyzing`、`analyzed`、`analysis_failed`、`archived`。
- 信息详情需要分层展示来源、抓取尝试、当前正文版本、AI 分析版本、股票关联建议、实体提及和待核实事项。AI 建议不得与用户确认的关联混在一起显示。
- 设置页的 AI 接口配置应支持 OpenAI Compatible Provider 的新增、查看、更新、删除和测试连接；页面永远不显示完整 API Key。
- 个股详情和今日页可以引用已确认或待确认的信息关联，但必须保留“AI 建议/用户确认/用户拒绝”的状态表达。
- 抓取失败、AI 失败、空正文和部分字段缺失均应只影响对应模块，不得导致信息中心、个股详情或今日页整体不可用。

## 第三阶段前端真实 API 联调页面（历史阶段记录）

- `/login`：接入后端登录、`/auth/me` 和退出后的重新登录流程；不开放公众注册，不提供邮件找回密码，不在前端保存 Session Token。
- `/information`：接入信息列表、筛选、分页、手动文本录入、单个公开 URL 录入和股票基础目录搜索；不实现全站爬虫或真实公告资讯订阅。
- `/information/[itemId]`：接入信息详情、来源记录、正文版本、AI 分析版本、股票关联确认/拒绝/新增、补充正文、重新抓取、分析和归档。
- `/settings/ai`：接入 AI Provider 列表、新增、编辑、测试和删除；页面不展示完整 API Key。
- 第三阶段历史边界：当时 `/today`、`/watchlist`、`/watchlist/[stockId]`、`/market-review/[date]`、`/reviews`、`/notifications`、`/settings/notifications` 仍为 Mock 页面；第四阶段起 `/reviews`、`/reviews/[reviewId]`、`/notifications` 和 `/settings/notifications` 的站内通知部分已接真实 API。

## 第四阶段前端真实 API 页面

- `/reviews`：接入真实用户每日复盘列表、日期/状态筛选和生成指定日期复盘。
- `/reviews/[reviewId]`：接入真实复盘详情、重新生成、程序聚合、AI 解释、来源追溯和历史版本。
- `/notifications`：接入真实站内通知列表、未读数量、筛选、已读/未读、归档、批量已读和 deep_link 跳转。
- `/settings/notifications`：站内通知偏好接真实 API；微信公众号区域继续保持 Mock 说明。
- 继续 Mock：`/today`、`/watchlist`、`/watchlist/[stockId]`、`/market-review/[date]`、估值中心、微信公众号状态和微信消息预览。
