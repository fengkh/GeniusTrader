# 官方公告与财经资讯数据源可行性 Spike 报告草案

## 第六阶段承接结论

第五阶段 Spike 的结论已进入第六阶段的受控实现：只实现上市公司公告候选收件箱试点，不冻结正式公告供应商，不开发财经新闻自动采集。CNINFO 和 SSE_DISCLOSURE 在数据库中以 disabled experimental source 形式注册；深交所、北交所、政府、国际机构和财经媒体仅保留为未来评估对象。

第六阶段实现必须继续遵守 Spike 结论：公开可访问不等于授权；技术可达不等于允许长期缓存、全文解析、AI 摘要、再展示或商业使用；PDF 可下载不等于允许保存原始文件。财经资讯仍以用户手动 URL 和补充文本为主。

本报告记录第五阶段“官方公告与财经资讯数据源可行性 Spike”的阶段性结论。它只评估公开来源的技术可达性、字段覆盖、增量同步、PDF 处理、去重、成本和合规风险，不代表任何数据供应商已被选定为 GeniusTrader V1 正式供应商。

## 四、公告字段覆盖结论

- 公告核心字段建议冻结为：来源、来源内 ID、标题、发布时间、采集时间、证券代码、市场、公司名称、来源页面 URL、文档 URL、文档类型、原始元数据哈希、去重键。
- CNINFO 样本覆盖公告来源内 ID、标题、发布时间、股票代码和 PDF URL，完整度较好。
- 上交所样本可验证公告列表和 PDF URL，但样本量较小。
- 深交所和北交所本轮不足以判断正式可用性。
- 多证券公告、更正公告、同一公告多渠道重复、公告分类字段口径仍需在真实 Provider 设计前确认。

## 五、PDF 可行性结论

- 本轮探测 PDF 6 个，4 个可下载并抽取文本，2 个因样本大小超过 Spike 上限而停止。
- 可抽取文本的 PDF 不代表系统可以长期保存或再展示全文。
- 第一版建议优先保存公告元数据、原始链接、文档哈希和必要摘要，完整 PDF 留存、OCR、全文索引和再展示规则必须先完成授权与产品确认。
- PDF 解析失败时，不得阻断公告元数据入库和来源链接展示。

## 六、资讯来源结论

- 公开资讯网页的结构、日期字段、正文抽取和版权边界显著弱于正式公告。
- 本轮只建议把证监会、交易所等官方页面作为“用户手动链接录入”和“未来授权审查”的来源候选。
- 不建议在 MVP 中冻结自动财经资讯 Provider。
- 普通新闻、媒体转载、付费内容、登录内容、评论区、反爬限制页面和平台讨论内容仍保持用户粘贴链接与补充文本为主。

## 七、增量同步建议

- 增量游标建议使用 `provider + capability + last_published_at + last_provider_id + overlap_window`。
- 只使用发布时间会漏掉同一时间多条公告或补发公告。
- 只使用采集时间会导致重复和跨日归属不稳定。
- 生产实现应保留重叠窗口，并通过来源 ID、规范化 URL、标题、证券代码和发布时间做幂等去重。

## 八、去重和事件聚合建议

- 精确去重：使用来源、来源 ID、规范化 URL、标题、证券代码、发布时间组合生成去重键。
- 近似去重：只作为辅助提示，不得直接删除原始来源记录。
- 事件聚合：可按同一证券、同一业务日期、标题前缀或相似标题聚合为一个事件组。
- 转发、转载或重复披露不得被计算为独立确认来源。
- AI 可以解释聚合后的差异，但不得覆盖原始公告或资讯事实。

## 九、成本与性能初判

- 本轮 Provider 级平均延迟约 1 秒，实际 14 次 HTTP 请求完成在 20 秒以内。
- 对 10、50、200 只自选股，建议优先采用“按市场和日期批量拉取 + 按自选股回填匹配”的混合方式。
- 不建议对每只股票逐个调用所有来源作为日常方案。
- 请求频率、失败重试、缓存和并发限制必须等授权与供应商规则确认后再定。

## 十、合规与授权风险

- 本报告不是法律意见。
- 技术可访问不等于允许自动采集、长期保存、全文解析、AI 摘要、再展示或商业化使用。
- 正式接入前必须确认来源站点条款、robots、接口授权、引用边界、缓存期限、全文存储、PDF 留存和用户可见再展示规则。
- 不得绕过登录、验证码、访问控制、反爬限制或付费墙。
- 不得保存用户 Cookie、个人账号凭证或来源站点临时会话作为采集能力。

## 十一、Provider Adapter 初稿

建议未来生产适配器至少输出以下结构：

- `ProviderProbeResult`：Provider 能力、状态、错误、延迟、样本数和限制说明。
- `AnnouncementRecord`：公告元数据、证券关系、文档 URL、哈希、去重键和字段完整度。
- `NewsRecord`：资讯元数据、来源类型、正文抽取状态、关联实体、哈希、去重键和字段完整度。
- `ProviderCursor`：增量同步游标、重叠窗口和最后成功同步信息。
- `ProviderStatus`：`PASS`、`PARTIAL`、`DATA_INSUFFICIENT`、`ACCESS_DENIED`、`RATE_LIMITED`、`TIMEOUT`、`NETWORK_ERROR`、`PARSE_ERROR`、`LEGAL_UNCLEAR`、`NOT_TESTED`。

## 十二、推荐决策

- 公告：CNINFO 可作为下一轮“公告 Provider Adapter 设计”的技术候选，上交所作为备选验证来源。
- 深交所和北交所：保留为待验证来源，不进入正式冻结。
- 财经资讯：不在 MVP 中冻结自动资讯 Provider，继续以用户粘贴链接和补充文本为主。
- 正式供应商：本轮不冻结任何正式公告或资讯供应商。
- 下一步：产品负责人先确认授权、留存、再展示和 PDF 策略，再决定是否进入“公告 Provider Adapter 技术方案”。

## 十三、仍需确认的问题

- 是否允许自动访问、缓存和展示 CNINFO、交易所公告元数据。
- 是否允许下载、解析、长期保存或再展示公告 PDF 全文。
- 是否仅保存标题、链接、发布时间和哈希，还是允许保存正文摘要。
- 资讯页面是否只做用户手动 URL 补充，还是进入受控官方资讯采集。
- 深交所和北交所是否需要专门二次 Spike。
- 是否需要采购授权聚合源替代免费公开页面。
- 公告和资讯失败时，站内通知是否只提示来源状态，不生成内容结论。
