# GeniusTrader 第一版产品简介

## 一句话定位

GeniusTrader 是一套支持用户自定义 AI 模型的 A 股自选股复盘与多源舆情管理平台，第一版聚焦私人测试场景下的收盘后复盘闭环。

## 目标用户

1. 有固定 A 股自选股池，并希望每天复盘的个人投资者。
2. 关注公告、资讯、社区观点和短视频内容，但需要统一整理和去噪的研究型用户。
3. 愿意使用自带 AI API，并理解 AI 只能辅助摘要、分类和复盘的用户。
4. 需要沉淀关注原因、核心逻辑和历史变化的用户。

## 核心价值

- 把分散的行情、公告、资讯和舆情链接沉淀到每只自选股。
- 区分客观数据、外部事实、观点、传闻、AI 判断和用户笔记。
- 让复盘有统一结构、历史版本和来源追踪。
- 在 AI 失败或不可用时，确定性数据仍可正常查看。

## MVP 范围

MVP 包含：

1. 私人测试版账户体系和用户数据隔离。
2. 一个主自选股池、个人分组、用户标签和关注逻辑。
3. 日级行情、最新行情快照和程序计算指标展示。
4. 公告、资讯、交易所公开信息和舆情链接的来源追踪。
5. 舆情收件箱和博主关注的人工确认式半自动流程。
6. 用户自带 AI API 配置、测试连接和调用记录。
7. 单股每日复盘、整体复盘、AI 原始版本和人工修订版本。
8. 系统预设异动规则和网页内异动展示。
9. 昨日观察条件的次日展示、验证状态标记和复盘材料回流。
10. 用户可见的数据来源状态、最后更新时间、同步中、数据过期、部分失败和完全失败状态。
11. 真实站内通知中心和通知偏好，用于承接当前已实现的用户每日复盘、重要信息、待核实事项和 AI 失败事件；公告、异动、观察条件、估值和系统事件作为未来事件来源。

MVP 不包含：

1. 券商账户、自动交易、下单、跟单或持仓资金管理。
2. 自动买卖点、荐股、收益预测或收益承诺。
3. 公众自由注册、支付、会员、用户社区或公开荐股。
4. 原生 iOS 或 Android App。
5. 全网社交平台爬虫、图片理解、OCR、秒级舆情监控。
6. 复杂量化回测或多 Agent 无限自主讨论。
7. 复盘 Markdown 导出不作为核心 MVP 验收项，暂列 P1 增强功能。
8. 微信公众号、邮件、Web Push、移动 Push 或短信的真实发送能力。

## 第一版导航

桌面端一级导航为：今日、自选股、信息中心、复盘历史、设置。

- 今日优先展示数据日期、来源状态、最后更新时间、自选股整体表现、重大异动、重大公告与重要资讯、板块和个人分组表现、舆情变化与待核实信息、今日整体复盘、待处理舆情和未完成复盘。AI 整体复盘不得放在客观行情、异动和重大信息之前。
- 自选股承载自选股列表、分组与标签、批量导入和个股详情。
- 信息中心通过 Tab 或二级导航承载公告与资讯、舆情收件箱、博主关注和待核实信息。
- 复盘历史当前承载真实用户私有信息每日复盘、历史版本、AI 解释和来源追溯；单股每日复盘、自选股整体复盘和全市场复盘继续按后续阶段迭代。
- 设置承载 AI 接口配置、模型任务配置、个人设置、数据源状态和管理员账户管理。
- 顶部通知铃铛和今日页通知摘要进入站内通知中心；通知设置作为设置下的二级页面，不新增一级导航。

移动端底部导航建议为：今日、自选股、信息、复盘、更多。设置和管理员功能放入“更多”。

## 第一版成功标准

第一版成功不是“给出投资结论”，而是让用户可以在一个工作台中完成：

1. 维护自选股和关注逻辑。
2. 查看带来源和更新时间的确定性数据。
3. 录入并整理舆情线索。
4. 生成并修订每日复盘。
5. 在次日验证昨日观察条件，并回看历史复盘和关注逻辑变化。

## 私人测试规模

首批私人测试用户控制在 10 人以内，技术容量按 50 人以内验证。第一版不为该规模引入微服务或复杂分布式架构，也不得在数据库或业务逻辑中写死 10 人限制。

## 产品设计原则

- 事实优先于观点。
- 正式公告优先于平台讨论。
- 原始数据与 AI 结论分开展示。
- 外部信息必须携带来源和时间。
- 确定性计算交给程序，文本理解和总结交给 AI。
- 未经证实的信息不得表达为事实。
- 用户可以修正自动分类和 AI 结论。

## 全市场复盘、估值与通知融合原型

2026-07-22 起，新增“全市场每日复盘、个股估值中心与用户通知中心融合原型”。该阶段基于既有 Spike 报告结果，只验证页面承载、核心跳转、状态表达和产品边界，不代表已经进入正式后端、真实数据或真实外部通知开发。

本能力仍遵守第一版边界：

- 不接入券商账户，不提供交易、荐股、仓位建议或收益保证。
- 全市场、板块、热门股票和估值结果均由程序基于可追溯数据计算，AI 只能解释结构化结果和数据缺口。
- 估值表达统一使用估值区间、合理价值区间、内在价值估计、市场隐含估值和估值置信等级，不把估值结果写成确定事实。
- 交易量、成交额和换手率只能反映流动性和关注度，不能直接证明公司内在价值。
- 候选 Provider 仍未确定；Tushare、AKShare、efinance 和 BaoStock 仅处于可行性验证范围。
- 站内通知已进入真实 `in_app` 闭环；微信公众号只保留未来架构和 Mock 状态，不实现真实绑定、OAuth、模板消息或 API 调用。
- 全市场复盘摘要位于今日页自选股整体表现之后，不得压过客观行情、重大异动和公告资讯。

## 第四阶段真实闭环

第四阶段实现用户私有信息每日复盘、BusinessEvent、站内 Notification、站内 NotificationPreference 和 `/reviews`、`/reviews/[reviewId]`、`/notifications`、`/settings/notifications` 的真实 API 联调。

该闭环不接入真实行情 Provider、全市场复盘后端、估值后端、自动调度、任务队列、微信公众号、邮件、Web Push 或移动 Push。
