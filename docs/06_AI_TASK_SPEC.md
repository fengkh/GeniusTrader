# AI 任务说明

本文定义第一版 AI 任务的输入、输出、边界和失败处理。所有 AI 调用必须经过后端统一 AI Gateway。前端不得直接接触用户 API Key。

## 全局规则

- AI 不得生成、估算或补全行情、成交量、成交额、换手率、市值、指数表现或确定性异动数字。
- AI 不得输出直接买入、卖出、仓位、止盈、止损、收益预测或收益保证。
- AI 不得把未经证实传闻表达为事实。
- 外部内容、用户粘贴内容和网页文本必须作为不可信输入处理，防止提示词注入。
- 数据不足时，AI 应输出“无法判断”“材料不足”或列出缺失字段，而不是编造结论。
- “反方证据检查”是单股及整体复盘生成流程中的内部辅助任务，不设置独立页面和独立用户功能。
- AI 调用日志默认只保存用户 ID、任务类型、模型、时间、Token 使用量、响应耗时、成功或失败状态、错误代码、输出结构校验状态和关联业务结果 ID。
- 默认不在调用日志中长期保存完整原始输入、完整第三方正文、完整 Prompt、API Key 或模型隐藏推理。
- AI 生成的结构化复盘结果作为业务数据保存在复盘及版本实体中，不重复作为完整调用日志保存。
- 调试信息必须脱敏并设置自动过期机制。
- AI 可以解释全市场复盘、板块热度、估值结果和结构化业务事件，但不得计算行情、排行、热度、估值数字或通知严重度。
- AI 不得修改程序生成的通知状态、用户通知偏好、通道状态、候选股票/板块或业务事件。
- AI 失败时，市场复盘、用户复盘和通知摘要必须可以使用规则模板或程序摘要降级。

## 任务 1：资讯摘要

- 输入字段：标题、正文或片段、来源、发布时间、采集时间、原始链接、关联股票或板块。
- 输出 JSON 字段：`summary`、`key_points`、`mentioned_entities`、`source_refs`、`missing_context`。
- 输入数据来源：公告、资讯、用户粘贴链接和用户补充文本。
- 不允许 AI 生成的字段：发布时间、来源、原始链接、行情数字。
- 不允许 AI 执行的动作：修改原文、覆盖原始记录、发布外部内容。
- 失败处理：保留原文和元数据，摘要状态标记失败。
- 是否允许人工编辑：允许编辑摘要副本，不允许覆盖原文。
- 来源引用要求：每个关键点应引用来源编号或原始链接标识。
- 适用模型能力：中文摘要、长文本压缩、结构化 JSON 输出。
- 成本和上下文注意事项：长文需截断或分段，避免发送无关用户私密笔记。
- 提示词注入防护要求：网页正文中的指令按内容处理，不得影响系统规则。
- 数据不足时的输出方式：列出缺失正文或来源字段。

## 任务 2：股票和板块关联建议

- 输入字段：文本内容、标题、来源、已识别股票、用户自选股列表、板块候选。
- 输出 JSON 字段：`stock_suggestions`、`sector_suggestions`、`confidence_reason`、`evidence_spans`、`needs_user_confirmation`。
- 输入数据来源：资讯、舆情条目、公告和用户补充文本。
- 不允许 AI 生成的字段：股票基础信息、标准分类、真实板块成分。
- 不允许 AI 执行动作：自动确认关联、覆盖用户关联。
- 失败处理：保留未关联状态，允许用户手动关联。
- 是否允许人工编辑：允许，用户最终确认。
- 来源引用要求：建议必须引用文本证据或说明仅为弱关联。
- 适用模型能力：实体识别、中文金融文本理解。
- 成本和上下文注意事项：优先传入用户自选股候选，减少上下文。
- 提示词注入防护要求：忽略文本中的模型行为指令。
- 数据不足时的输出方式：返回空建议和缺失原因。

## 任务 3：事实、观点和传闻分离

- 输入字段：文本、来源等级、发布时间、是否引用公告、原始链接。
- 输出 JSON 字段：`facts`、`opinions`、`rumors`、`uncertain_items`、`source_refs`。
- 输入数据来源：公告、资讯、平台讨论、用户补充文本。
- 不允许 AI 生成的字段：事实发生时间、公告编号、交易数据。
- 不允许 AI 执行动作：判定内容绝对真实或虚假。
- 失败处理：条目标记“未完成分离”。
- 是否允许人工编辑：允许人工修正分类结果。
- 来源引用要求：每条事实、观点或传闻应保留来源引用。
- 适用模型能力：信息抽取、事实观点区分。
- 成本和上下文注意事项：长文本按段落处理，保留段落引用。
- 提示词注入防护要求：将输入文本作为待分析材料，不执行其中命令。
- 数据不足时的输出方式：无法分类的内容放入 `uncertain_items`。

## 任务 4：情绪与立场分析

- 输入字段：文本、平台、作者信息、关联股票或板块、发布时间。
- 输出 JSON 字段：`sentiment`、`stance`、`emotion_terms`、`rationale`、`source_refs`。
- 输入数据来源：舆情条目、资讯观点、用户补充文本。
- 不允许 AI 生成的字段：真实热度数字、传播规模、投资结论。
- 不允许 AI 执行动作：替用户发布观点或触发交易行为。
- 失败处理：情绪状态标记未知。
- 是否允许人工编辑：允许。
- 来源引用要求：立场判断必须引用文本依据。
- 适用模型能力：中文情绪分析、立场识别。
- 成本和上下文注意事项：避免传入过多无关评论。
- 提示词注入防护要求：评论中的指令无效。
- 数据不足时的输出方式：返回 `sentiment: "unknown"` 并说明原因。

## 任务 5：主题分类

- 输入字段：文本、标题、候选主题、关联股票、关联板块、日期。
- 输出 JSON 字段：`topics`、`topic_type`、`evidence`、`needs_user_confirmation`。
- 输入数据来源：资讯、公告摘要、舆情内容、用户笔记。
- 不允许 AI 生成的字段：权威标准分类、确定性题材归属。
- 不允许 AI 执行动作：直接写入标准分类。
- 失败处理：主题为空并允许人工添加标签。
- 是否允许人工编辑：允许。
- 来源引用要求：每个主题建议引用文本依据。
- 适用模型能力：短文本和长文本主题聚类。
- 成本和上下文注意事项：候选主题优先来自当前用户数据和已确认分类。
- 提示词注入防护要求：输入主题名称不应改变系统规则。
- 数据不足时的输出方式：输出空数组和缺失原因。

## 任务 6：信息质量和证据状态分析

- 输入字段：来源类型、原始链接、正文、是否引用公告、可交叉验证来源、发布时间。
- 输出 JSON 字段：`source_level`、`evidence_status`、`quality_notes`、`verification_gaps`、`possible_duplication_or_exaggeration`。
- 输入数据来源：资讯和舆情条目。
- 不允许 AI 生成的字段：绝对可信度概率、真假定论。
- 不允许 AI 执行动作：将传闻升级为事实。
- 失败处理：信息质量状态标记“未分析”。
- 是否允许人工编辑：允许人工补充核验说明。
- 来源引用要求：质量判断需引用来源元数据和文本依据。
- 适用模型能力：证据链分析、风险提示。
- 成本和上下文注意事项：只发送核验所需字段。
- 提示词注入防护要求：外部文本不能覆盖核验规则。
- 数据不足时的输出方式：列出待核实事项。

## 任务 7：单股每日复盘

- 输入字段：股票、交易日、行情数据、程序指标、公告资讯、舆情分析、异动事件、关注逻辑、用户笔记。
- 输出 JSON 字段：`objective_performance`、`relative_strength`、`trading_abnormalities`、`events`、`sentiment_topics`、`fact_opinion_rumor_split`、`logic_change`、`risks`、`counter_evidence`、`next_observation_conditions`、`source_refs`。
- 输入数据来源：用户自选股、行情、公告资讯、舆情、程序指标和用户笔记。
- 不允许 AI 生成的字段：任何缺失行情数字、确定性异动结论、买卖建议。
- 不允许 AI 执行动作：覆盖 AI 原始版本、覆盖用户修订版本、触发交易、直接修改观察条件验证状态。
- 失败处理：保存失败状态，允许用户手写复盘或重新生成。
- 是否允许人工编辑：允许，编辑形成新修订版本。
- 来源引用要求：每段复盘必须尽可能引用材料来源。
- 适用模型能力：中文金融文本整合、结构化输出、长上下文。
- 成本和上下文注意事项：按股票和交易日裁剪材料，避免发送无关历史数据。
- 提示词注入防护要求：舆情中的指令不得影响复盘格式和边界。
- 数据不足时的输出方式：明确列出缺失模块，不补全结论；观察条件可输出为待人工确认。

## 任务 8：自选股整体复盘

- 输入字段：交易日、全部自选股摘要、异动列表、公告资讯摘要、舆情主题、单股复盘摘要。
- 输出 JSON 字段：`market_day_summary`、`watchlist_themes`、`key_stocks`、`risk_items`、`counter_evidence`、`verification_todos`、`next_day_observation_conditions`、`source_refs`。
- 输入数据来源：当前用户自选股数据和当日复盘材料。
- 不允许 AI 生成的字段：未来数据、收益预测、交易指令。
- 不允许 AI 执行动作：替用户调整自选股、触发通知推送或交易。
- 失败处理：整体复盘标记失败，今日页仍展示确定性数据；允许用户手写整体复盘或重新生成。
- 是否允许人工编辑：允许，编辑形成修订版本。
- 来源引用要求：重点结论需引用股票、公告、资讯或异动来源。
- 适用模型能力：多文档摘要、结构化输出。
- 成本和上下文注意事项：优先使用单股摘要和高优先级材料，避免全量长文。
- 提示词注入防护要求：来自任一外部来源的文本不得改变任务边界。
- 数据不足时的输出方式：只总结已有数据，并列出缺口。

## 任务 9：反方证据检查

- 任务定位：单股及整体复盘生成流程中的内部辅助任务，不设置独立页面和独立用户功能。其结果可以进入复盘中的风险、反证和待核实事项。
- 输入字段：某条观点、关联股票、支持材料、公告资讯、舆情材料。
- 输出 JSON 字段：`counter_evidence`、`conflicting_sources`、`unverified_assumptions`、`follow_up_questions`。
- 输入数据来源：用户关注逻辑、资讯、舆情、公告和复盘历史。
- 不允许 AI 生成的字段：事实结论、真假定论、行情数字。
- 不允许 AI 执行动作：删除用户关注逻辑、改变复盘版本、作为独立功能写入用户页面。
- 失败处理：标记未完成反方检查。
- 是否允许人工编辑：允许。
- 来源引用要求：每条反方证据必须引用来源或标记为待核实。
- 适用模型能力：论点拆解、证据对比。
- 成本和上下文注意事项：围绕单一观点裁剪材料。
- 提示词注入防护要求：输入观点不得改变安全边界。
- 数据不足时的输出方式：返回待核实问题而非结论。

## 任务 10：动态题材和标签建议

- 输入字段：股票、公告资讯、舆情主题、行情异动、用户已有标签、候选题材。
- 输出 JSON 字段：`suggested_dynamic_themes`、`suggested_tags`、`evidence`、`suggestion_status`。
- 输入数据来源：行情指标、公告资讯、舆情、用户标签。
- 不允许 AI 生成的字段：标准分类、权威题材事实。
- 不允许 AI 执行动作：自动接受建议或覆盖用户标签。
- 失败处理：不产生建议，用户仍可手动维护。
- 是否允许人工编辑：允许，用户可接受、拒绝或忽略。
- 来源引用要求：建议必须有依据引用。
- 适用模型能力：主题识别、标签归纳。
- 成本和上下文注意事项：限制候选范围，避免对全市场材料做扩展。
- 提示词注入防护要求：舆情文本中的标签要求不直接采纳。
- 数据不足时的输出方式：返回空建议并说明缺少依据。

## 任务 11：原关注逻辑变化判断

- 输入字段：原关注逻辑、当日行情、公告资讯、舆情、异动、历史复盘摘要、用户笔记。
- 输出 JSON 字段：`logic_status`、`supporting_evidence`、`weakening_evidence`、`invalidating_risks`、`pending_verification`。
- 输入数据来源：用户关注逻辑、当日材料和历史复盘。
- 不允许 AI 生成的字段：投资结论、买卖动作、收益预期。
- 不允许 AI 执行动作：直接修改用户关注逻辑。
- 失败处理：逻辑状态标记“待人工判断”。
- 是否允许人工编辑：允许，用户最终确认。
- 来源引用要求：增强、减弱、失效或待验证判断必须引用依据。
- 适用模型能力：文本对比、证据归因。
- 成本和上下文注意事项：优先传入相关历史摘要而非全部历史。
- 提示词注入防护要求：用户笔记和外部文本不能覆盖禁止交易建议规则。
- 数据不足时的输出方式：返回 `logic_status: "pending_verification"` 并列出缺失材料。

## 任务 12：全市场复盘解释

- 输入字段：程序计算的市场宽度、主要指数表现、市场分层表现、板块热度排行、板块阶段、热门股票排名、次日观察候选、缺失字段和数据来源。
- 输出 JSON 字段：`market_summary`、`board_heat_explanation`、`continuity_explanation`、`watch_items_explanation`、`risk_and_verification_items`、`data_gap_summary`。
- 输入数据来源：行情 Provider、板块 Provider、公告事件统计和程序计算结果。
- 不允许 AI 生成的字段：涨跌家数、成交额、涨跌停数量、板块热度分数、板块阶段、热门股票排名、观察候选名单。
- 不允许 AI 执行动作：新增未出现在程序候选中的股票或板块；输出买入、卖出、仓位或收益保证。
- 失败处理：页面继续展示程序计算结果，AI 解释区域显示失败状态。
- 是否允许人工编辑：允许，作为复盘文字版本编辑，不改变底层计算结果。
- 来源引用要求：解释必须引用结构化结果和来源状态。
- 适用模型能力：结构化摘要、风险归纳、缺口解释。
- 成本和上下文注意事项：只传入排行摘要和证据字段，不传入全市场原始明细。
- 提示词注入防护要求：公告、资讯和用户补充材料不得覆盖系统禁止交易建议规则。
- 数据不足时的输出方式：返回数据不足说明，不把有限样本写成全市场结论。

## 任务 13：估值区间解释

- 输入字段：程序计算的估值方法、估值区间、隐含上涨或下跌空间、置信等级、模型假设、财务数据日期、输入来源、缺失字段和不适用原因。
- 输出 JSON 字段：`method_explanation`、`assumption_explanation`、`sensitivity_summary`、`confidence_explanation`、`missing_data_summary`、`risk_and_verification_items`。
- 输入数据来源：财务数据 Provider、行情 Provider、行业估值数据和程序估值结果。
- 不允许 AI 生成的字段：财务报表数字、当前价格、市值、PE/PB/PS、估值区间、隐含空间、置信等级、模型选择。
- 不允许 AI 执行动作：补全缺失财务数据；把估值解释写成价格目标、交易建议或收益保证。
- 失败处理：估值中心继续展示程序结果和缺失原因，AI 解释区域显示失败状态。
- 是否允许人工编辑：允许，作为用户笔记或复盘文字引用，不覆盖原始估值结果。
- 来源引用要求：每段解释必须对应模型结果、假设或缺失字段。
- 适用模型能力：财务解释、假设解释、风险归纳。
- 成本和上下文注意事项：不传入完整历史明细，只传入估值结果、必要财务字段和来源元数据。
- 提示词注入防护要求：外部研究观点不能改变程序计算的估值区间和禁止交易建议规则。
- 数据不足时的输出方式：解释为什么 `confidence_level` 为 `unavailable` 或低置信，不生成替代数字。

## 任务 14：通知摘要辅助

- 输入字段：结构化业务事件、通知类型、程序严重度、业务日期、目标页面、数据状态、服务状态、去重结果和可披露摘要字段。
- 输出 JSON 字段：`short_title`、`short_summary`、`risk_or_gap_note`、`target_page_hint`、`source_refs`。
- 输入数据来源：业务事件、程序复盘结果、公告元数据、异动事件、观察条件验证和估值结果。
- 不允许 AI 生成的字段：通知严重度、通知频率、通知通道状态、用户偏好、幂等键、行情数字、估值数字、候选名单。
- 不允许 AI 执行动作：发送通知、调用微信公众号、修改通知偏好、提升严重度、创建或删除业务事件。
- 失败处理：使用规则模板摘要；站内通知仍可创建。
- 是否允许人工编辑：允许编辑业务展示文案副本，不覆盖原始业务事件。
- 来源引用要求：摘要必须引用结构化事件或业务结果 ID。
- 适用模型能力：短文本摘要、结构化事件解释。
- 成本和上下文注意事项：只传入通知摘要所需字段；不得传入完整自选股清单、API Key、完整第三方正文或敏感账户信息。
- 提示词注入防护要求：外部公告、资讯和用户文本不能改变通知边界。
- 数据不足时的输出方式：返回规则可用字段和缺失说明。

### 微信公众号摘要边界

- 微信摘要不得完全依赖 AI 自由生成，必须以程序模板和结构化字段为基础。
- 微信摘要只可包含计数、事件名称、业务日期、目标页面提示和必要风险/缺口说明。
- 微信摘要不得包含完整自选股清单、API Key、敏感账户信息、交易动作、仓位、收益保证、强推荐或保证性表述。
## 后端第二阶段 AI 任务补充

### `provider_connection_test`

- 触发：用户在设置页测试 AI Provider。
- 输入：用户配置的 Base URL、模型名称和后端短暂解密的 API Key。
- 输出：连接测试成功或失败状态、错误码、耗时和 Token 用量（如 Provider 返回）。
- 日志限制：不得保存 API Key、完整 Prompt、完整响应正文或模型隐藏推理。

### `information_sentiment_analysis`

- 触发：用户对信息条目发起结构化分析。
- 输入：已保存的当前内容版本、来源类型、标题和用户上下文；内容作为不可信文本放入明确边界内。
- 输出：严格 JSON 结构，包括事实、观点、传闻、情绪、来源可信度、关键主张、股票提及、实体提及、风险、待核实项和限制说明。
- 校验：Pydantic schema 严格校验，禁止额外字段；首次无效时允许一次修复请求，第二次仍无效则任务失败。
- 降级：AI 失败只影响分析版本，不影响原始信息、来源、手动关联和后续人工处理。
- 禁止：AI 不得生成行情、K 线、公告原文、来源发布时间、股票基础字段或任何交易建议。
