# 核心用户流程

## 第六阶段前置子阶段 6A：证券目录到真实自选股流程

1. 管理员进入设置中的证券目录页面。
2. 管理员确认当前来源状态、功能开关和目录缺口。
3. 管理员在 development 环境中手动选择 SSE、SZSE、BSE 或全部可用来源发起同步。
4. 系统通过 `SecurityMasterProvider` 请求候选来源，标准化 A 股普通股票并 upsert 本地 `stocks`。
5. 同步完成后，系统展示 sync run 状态、接收数、新增数、更新数、不变数、失败数、来源和数据缺口。
6. 普通用户进入自选股页，通过本地搜索查找股票，不直接请求第三方来源。
7. 用户选择搜索结果中的真实 `stock_id`，填写分组、标签和关注原因后加入自选股。
8. 用户编辑分组、标签和关注原因，或移除后重新添加。
9. 后续公告匹配读取真实 `stocks` 和当前用户自选股，不依赖硬编码开发种子。

失败分支：来源关闭、真实网络关闭、Provider 不可用、接口结构变化、网络失败、目录仍只有开发样本、股票不可搜索、重复添加或超过 200 只上限均返回明确状态；失败不得清空既有 `stocks` 或用户自选股，也不得自动触发公告同步、AI 分析、BusinessEvent 或通知。

## 第六阶段补充：公告候选人工导入流程

1. 用户进入信息中心的公告候选收件箱。
2. 用户确认页面上的实验说明和来源状态。
3. 用户选择来源、日期范围和当前自选股范围，手动发起同步。
4. 系统只针对当前用户自选股调用已启用的实验 Provider，生成同步运行记录。
5. 系统标准化公告元数据、去重并匹配已有股票，生成用户私有候选。
6. 用户查看候选详情，可标记已查看、忽略、恢复，或按需提取 PDF 文本。
7. 用户选择元数据导入、提取正文导入或补充文本导入。
8. 系统创建 InformationItem 和 ingestion link，不自动 AI 分析、不自动通知。
9. 用户进入 InformationItem 详情页，按已有流程主动发起 AI 分析。
10. 导入后的 InformationItem 可以触发相关每日复盘 stale，并在下一次复盘中作为材料使用。

失败分支：功能关闭、来源未启用、真实网络关闭、Provider 限流、源结构变化、无自选股、无候选、PDF 不可用或导入重复均返回明确状态；其他页面和已有信息流程继续可用。

本文描述第一版最重要的用户流程，用于校验 MVP 是否形成完整复盘闭环。

## 流程 1：管理员创建测试账户

1. 管理员登录系统。
2. 进入设置中的管理员账户管理。
3. 创建用户账户或邀请测试用户。
4. 系统记录管理员、目标用户、操作类型和时间。
5. 用户获得账号后登录。
6. 如用户需要重置密码，管理员发起重置，系统生成一次性临时密码并设置有效期限。
7. 用户首次使用临时密码登录后必须修改密码。
8. 用户首次进入今日页，看到空自选股状态。

成功标准：普通用户无法访问管理员账户管理；管理员无法读取用户原密码；普通日志不记录完整临时密码；管理员操作可追溯。

## 流程 2：用户配置 AI API

1. 用户进入设置页。
2. 填写 OpenAI Compatible Base URL、API Key 和模型名称。
3. 选择默认模型和备用模型。
4. 点击测试连接。
5. 系统通过后端 AI Gateway 发起测试。
6. 页面显示测试结果和脱敏后的配置状态。

降级规则：测试失败时，用户仍可使用自选股、行情、公告、舆情录入和历史复盘查看功能。

## 流程 3：建立自选股池

1. 用户进入自选股页。
2. 通过本地证券目录搜索股票，或选择粘贴股票代码列表、CSV 导入等批量入口。
3. 用户必须从本地证券目录匹配到的股票中选择，添加请求只提交 `stock_id`，不得手写不存在的股票。
4. CSV 模板使用 `stock_code`、`group`、`tags`、`focus_reason` 字段，其中只有 `stock_code` 必填；CSV 也必须先匹配本地证券目录。
5. 系统校验 `stock_id`、可搜索状态和用户自选股去重，单条错误不阻断整个文件导入。
6. 成功股票进入用户主自选股池，失败、重复和可更新条目显示明细。
7. 对重复股票，系统默认不重复创建，并询问是否更新已有分组、标签和关注原因。
8. 用户为股票设置分组、标签、关注原因和核心逻辑。
9. 系统展示标准分类、系统建议和用户分类的分层结果。

成功标准：每位用户只有一个主自选股池；用户不能覆盖标准分类；用户不能通过代码或名称创建不存在股票；证券基本信息来自证券目录同步，行情、财务、估值和技术指标仍未接入真实数据。

## 流程 3A：扫描和筛选自选股

1. 用户进入自选股页。
2. 页面以桌面端紧凑表格或移动端紧凑行列表展示自选股。
3. 用户可以按股票名称或代码搜索。
4. 用户可以按个人分组、用户标签和板块筛选叠加过滤。
5. 板块筛选支持标准行业板块、标准概念板块和动态市场题材三种类型，同一时间选择一个主板块。
6. 页面展示筛选结果数量，并允许清除全部筛选。
7. 用户点击股票整行进入个股详情。

成功标准：板块筛选不是普通用户标签；移动端紧凑行可快速扫描，并清楚显示涨跌、停牌、过期和失败状态。

## 流程 4：录入舆情线索

1. 用户进入信息中心的舆情收件箱 Tab。
2. 粘贴来自抖音、小红书、雪球、同花顺、微信公众号或新闻网页的独立链接。
3. 系统保存链接、录入时间和平台信息。
4. 系统尝试合法解析公开信息。
5. 解析失败时，用户补充标题、正文、字幕摘要或个人说明。
6. 用户手动关联股票和板块，或查看 AI 的关联建议。
7. AI 对可用文本进行主题、情绪、事实/观点/传闻和信息质量分析。

成功标准：解析失败不阻断入库；用户补充内容与原始来源信息分开保存。

## 流程 5：查看交易异动

1. 系统基于预设规则和可用行情数据计算异动。
2. 用户在今日页看到今日重点异动摘要。
3. 用户从今日页进入异动聚合视图查看触发依据。
4. 用户进入个股详情查看异动对应的行情、公告、资讯和舆情。
5. 用户将异动作为单股复盘材料之一。

成功标准：每个异动展示异动类型、触发依据、对比基准、实际数据、规则版本和数据时间；AI 不决定确定性异动。

## 流程 6：生成并修订单股每日复盘

1. 用户进入个股详情页。
2. 查看股票身份、分时/日K图表、程序计算量化概览、分类、异动、公告、资讯、舆情和关注逻辑。
3. 点击生成单股复盘。
4. 系统聚合交易日内可用材料并调用 AI Gateway。
5. AI 生成结构化原始版本。
6. AI 失败时，用户可以重新生成，也可以直接手写复盘。
7. 用户人工编辑，形成修订版本。
8. 系统保存 AI 原始版本和人工修订版本。
9. 系统保存下一交易日观察条件。

成功标准：复盘不输出买入、卖出、仓位指令或收益保证；原始 AI 版本不可被覆盖。

## 流程 6A：查看个股图表和量化概览

1. 用户从自选股页、今日页或复盘历史进入个股详情。
2. 页面先展示股票名称、代码、市场、状态、最新价和涨跌幅。
3. 用户在分时和日K之间切换。
4. 用户查看价格线、均价线、昨收参考线、成交量、K线、MA5、MA10 和 MA20。
5. 用户查看量化概览中的数值、比较基准、历史分位或强弱条。
6. 数据过期或部分失败时，页面展示状态提示和最近可用数据；完全无图表数据时展示空状态。
7. 用户继续向下查看分类、公告资讯、舆情和复盘材料。

成功标准：图表和量化指标均标记模拟数据或来源状态；AI 不生成K线、分时和量化指标。

## 流程 7：生成自选股整体复盘

1. 用户进入今日页。
2. 系统汇总全部自选股当日表现、异动、公告、资讯和舆情。
3. 用户点击生成整体复盘。
4. AI 输出今日主线、重点股票、风险、待核实事项和下一交易日观察条件。
5. AI 失败时，用户可以重新生成，也可以直接手写整体复盘。
6. 用户确认或修订整体复盘。
7. 系统保存历史版本。

成功标准：整体复盘只使用目标交易日及之前的数据，不使用未来数据。

## 流程 8：回看历史复盘和关注逻辑变化

1. 用户进入复盘历史页。
2. 按日期、股票或分组筛选历史复盘。
3. 查看 AI 原始版本和人工修订版本。
4. 对比关注逻辑的增强、减弱、失效或待验证状态。
5. 进入个股详情更新后续观察条件或个人笔记。

成功标准：历史版本包含时间、作者类型和版本来源。

## 流程 9：查看数据状态并刷新

1. 用户进入今日页或个股详情。
2. 页面展示数据日期、数据来源状态和最后更新时间。
3. 页面打开时可以触发刷新。
4. 用户也可以手动刷新。
5. 系统展示正常、同步中、数据过期、部分失败或完全失败状态。
6. 如果行情、资讯、舆情或 AI 模块部分失败，其他可用模块继续展示。

成功标准：数据失败不导致整页不可用；每个外部数据模块有来源和更新时间。

## 流程 10：次日验证观察条件

1. 用户在前一交易日的单股或整体复盘中保存观察条件。
2. 下一交易日，今日页和个股详情展示昨日观察条件。
3. 用户根据当日事实标记为已发生、未发生、部分发生、无法判断或不再适用。
4. 系统保存验证状态、验证时间和用户备注。
5. 验证状态进入下一次复盘材料。

成功标准：观察条件可以跨交易日展示、标记和回流到复盘材料。

## 流程 11：查看全市场每日复盘和次日观察候选

1. 用户进入今日页。
2. 页面展示全市场数据日期、数据范围、来源状态和最后更新时间。
3. 用户查看市场宽度、主要指数、全市场成交额、涨跌家数、涨跌停数量和市场分层表现。
4. 用户进入 `/market-review/[date]`，查看板块热度排行、板块阶段、连续走强或退潮状态。
5. 用户展开板块内热门股票，查看排名依据、核心驱动、风险扣分和数据更新时间。
6. 用户查看次日观察板块、观察股票、继续观察条件、失效条件和待核实事项。
7. 用户可将观察条件作为后续复盘材料，但系统不得把候选解释为买卖建议。

成功标准：有限样本不冒充全市场；每个热度和排名结果都有可追溯数据、公式版本和缺失状态；AI 解释不得改变程序计算结果。

## 流程 12：查看个股估值中心

1. 用户进入个股详情。
2. 页面展示当前价格、总市值、财务数据日期和估值数据来源。
3. 系统展示程序选择的估值方法和不适用方法。
4. 用户查看悲观、基准和乐观估值区间、隐含上涨或下跌空间、估值置信等级和模型假设。
5. 如果财务字段、行业估值或报告期不可用，页面展示缺失字段和无法估值原因。
6. 用户可将估值解释和数据缺口作为复盘参考，但不得触发交易、仓位或收益保证流程。

成功标准：估值只使用目标日期及之前披露的数据；数据不足时不强迫输出估值数字；AI 不生成财务、估值或行情数字。

## 流程 13：查看和配置站内通知

1. 当前已实现业务模块完成用户每日复盘、重要信息标记、待核实事项发现或 AI 分析失败。
2. 系统产生 `BusinessEvent`，通知编排器根据事件类型、程序严重度、用户偏好和去重键创建站内通知。
3. 用户通过顶部通知铃铛、今日页通知摘要或移动端更多入口进入 `/notifications`。
4. 用户按全部、未读、每日复盘、重要信息、待核实、AI失败或已归档筛选通知。
5. 用户点击通知进入目标页面，例如 `/reviews/[reviewId]` 或 `/information/[itemId]`。
6. 用户可标记已读、标记未读、归档或批量标记已读。
7. 用户进入 `/settings/notifications` 查看和保存真实站内通知偏好。
8. 微信公众号区域仅显示未来规划，不绑定、不扫码、不调用微信 API。

成功标准：通知不会泄露其他用户数据；AI 不提升严重度、不修改偏好、不直接发送外部通知；微信公众号仅为原型状态，不实现真实绑定或发送。

## 流程 14：生成用户私有信息每日复盘

1. 用户先在信息中心保存手动文本或单个公开 URL，并补充或确认股票关系。
2. 用户对可用正文触发 AI 结构化分析，系统保存最新成功分析版本、事实、观点、传闻和待核实事项。
3. 用户进入 `/reviews`，选择今日或历史 `review_date`。
4. 系统按 `Asia/Shanghai` 计算信息归属日期，优先使用来源 `published_at`，缺失时使用信息创建时间。
5. 系统只纳入当前用户、未归档、同业务日期且有可用正文的信息。
6. 系统生成程序化 `rule_snapshot`：统计信息、选择最新成功分析版本、按 confirmed 股票关系分组，并把 suggested 关系放入待确认。
7. 如果用户已配置 AI Provider，系统调用 `user_daily_review_generation` 生成 AI 解释；AI 失败时保留规则复盘并标记为 partial。
8. 系统保存 `daily_review_versions`，旧版本不覆盖。
9. 系统创建 BusinessEvent 和真实站内通知。
10. 用户从 `/notifications` 点击通知进入 `/reviews/[reviewId]`。
11. 如果后续同日信息、分析版本或关系变化，复盘变为 stale，用户主动重新生成后清除 stale。

成功标准：复盘只使用当前用户私有信息；不代表全市场行情复盘；不输出买入、卖出、仓位、目标价或收益保证；来源可追溯到信息详情。
## 流程补充：受控信息录入与 AI 结构化分析

1. 用户进入信息中心，选择手动录入正文或粘贴一个公开 URL。
2. 系统保存信息条目、来源类型、用户备注和用户手动关联股票；URL 条目先进行协议、主机和私有地址校验。
3. URL 录入时，系统只抓取该单个 URL 的公开内容，不登录、不执行 JS、不抓二级链接、不绕过平台限制。
4. 抓取成功后生成内容版本；抓取失败时保留信息条目，提示失败原因，并允许用户补充正文。
5. 用户触发 AI 分析时，后端通过已启用的 AI Provider 调用统一 AI Gateway。
6. AI 输出必须通过结构化 schema 校验；首次校验失败可自动请求一次修复，第二次仍失败则保存失败版本。
7. 系统保存事实、观点、传闻、情绪、可信度、股票提及、实体提及、风险和待核实项。
8. AI 建议的股票关联默认为“待确认”，用户可确认或拒绝；用户手动添加的关联默认为“已确认”。

成功标准：信息条目、内容版本、分析版本和关联状态可追溯；AI 失败不删除原始信息；不同用户只能查看和处理自己的信息。

## 流程补充：前端真实 API 联调

1. 用户进入 `/login`，输入管理员创建的用户名和密码。
2. 后端登录成功后设置 HttpOnly Session Cookie 和 CSRF Cookie；前端只保存内存中的当前用户展示状态。
3. 用户进入 `/settings/ai`，新增或编辑 OpenAI Compatible Provider，API Key 只提交给后端加密保存，页面不回显完整密钥。
4. 用户在 `/information` 录入手动文本或单个公开 URL，并可搜索股票基础目录建立用户确认关联。
5. 用户进入 `/information/[itemId]`，查看来源、当前正文、AI 分析版本、待核实事项和股票关联状态。
6. 用户可以对 AI suggested 股票关联执行确认或拒绝，也可以手动新增 confirmed 关联。
7. URL 抓取失败时，用户补充正文；AI 分析失败时，来源、正文和人工关联仍可查看。

成功标准：前端所有写请求带 `X-CSRF-Token`；未登录访问真实 API 页面会进入登录流程；信息和 AI Provider 均按当前用户隔离；浏览器端不保存 Session Token、密码或完整 API Key。

## 流程补充：日级行情状态查看与管理员同步

1. 用户进入 `/today` 或 `/watchlist`。
2. 前端请求真实行情状态和当前用户自选股快照。
3. 如果没有真实快照，页面显示 unavailable、来源状态和授权待确认说明，不展示 Mock 价格或虚假 K 线。
4. 用户进入 `/watchlist/[stockId]`，只查看该股票已有日级快照；没有历史图表数据时展示未开放或暂无数据状态。
5. 管理员进入 `/settings/market-data`，查看 Provider 授权状态、最近同步和数据缺口。
6. 管理员在显式开关、管理员身份和 CSRF 校验通过后，可以触发行情同步。
7. 无真实 Token 时，同步返回 `MARKET_DATA_PROVIDER_NOT_CONFIGURED`，不写入部分行情，不破坏历史快照。

成功标准：普通用户不能触发行情同步；行情同步只引用已有股票；失败仅影响行情模块；不同用户的自选股行情列表按当前用户隔离。
